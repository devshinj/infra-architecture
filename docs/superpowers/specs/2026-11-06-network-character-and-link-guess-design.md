# 망 종류 지식과 망연계 예상 — 설계

날짜: 2026-11-06 · 상태: 승인됨 (2026-11-06)
앞선 문서: `2026-11-04-flows-and-network-boundaries-design.md` (흐름·망 경계, 구현되어 main 에 합쳐짐 558ec78)

표기: **(사용자)** = 사용자가 정한 것, **(제 판단)** = 설계자가 정한 것(사용자가 "나머지는 알아서"라고 맡김).

## 왜 하는가

실제로 있었던 일이다. 행정망(인트라넷) PC에서 GCloud 인터넷망의 WAS·WEB에 접근해야 했다. 두 망 사이에 통신 경로가 없어서 방화벽 허용 요청이 취소됐고, 방화벽 담당자에게서 "망연계가 필요하다"는 답을 받았다.

기관마다 이런 판단의 근거가 되는 내부 규정이 있지만, 도구가 처음부터 그 내용을 알 수는 없다. 그래서 도구는 다음 셋을 한다.
1. **일반 지식을 기본으로 갖춘다.** 흔한 망 종류와 망 사이를 잇는 보통의 방식을 알고 있다.
2. **사용자가 지식을 넣을 수 있다.** 기관의 망 이름과 규정에 따른 규칙을 사용자가 넣는다. **(사용자)**
3. **판정이 아니라 예상과 가이드를 준다.** 그 지식으로 "망연계가 필요할 가능성이 높다"는 것을 구성도를 그리는 시점에 미리 그려 보여 준다. 취소될 방화벽 요청을 미리 거르는 것이 목적이다. **(사용자)**

지금 상태로는 이 사례를 잡지 못한다. 망 영역(`network_zone`)에는 이름만 있고 종류가 없다. 또 방화벽 하나만 거치면 `network_direct` 경고가 사라지므로, "행정망 PC → 방화벽 → GCloud WAS" 그림이 아무 안내 없이 통과한다.

## 목표

### 1. 망 지식 (지식베이스)

**사용자가 정한 것.** 용어 사전 같은 "망 지식" 화면에서 직접 더하고 고친다. 넣은 지식은 모든 프로젝트에 같이 적용된다. **(사용자)**

**적용 범위.** 용어 사전(`glossaryTerms`)과 같게 계정 단위로 둔다. 그 계정의 모든 프로젝트·구성도에 적용된다. **(제 판단)** 팀 공유는 앞선 설계대로 나중 일이다.

#### 1-1. 망 종류

망 종류 한 항목에는 다음이 들어간다.
- 이름
- 다른 이름들: AI가 망 이름을 맞춰 볼 때 쓴다. 예: 행정망 → 정부 업무망, 행정 내부망
- 짧은 설명: 한두 문장, 쉬운 말
- 등급: 판정에 쓰는 값
- 출처: 기본 제공 또는 사용자

**등급은 네 가지다. (제 판단)**

| 등급 | 뜻 |
|---|---|
| 폐쇄 | 원칙적으로 바깥과 잇지 않는 망 |
| 내부 | 기관 안의 업무용 망. 인터넷과는 분리된다 |
| 경계 | DMZ처럼 안과 밖 사이에 두는 망 |
| 외부 | 인터넷이나 다른 기관과 닿는 망 |

**기본 제공 망 종류 후보. (제 판단)** 일반 지식 수준이며 기관마다 다를 수 있다. 정확한 목록과 설명은 만드는 사람이 다듬되, 이 범위를 덮어야 한다.
- **내부:** 행정망(정부 업무망), 업무망·내부망(인트라넷), 관리망(운영·관리 전용), 백업망, 개발·테스트망, 공공 클라우드 내부 영역(G-클라우드 업무존 등)
- **폐쇄:** 제어망(OT·SCADA), 금융 전산망 같은 완전 폐쇄망
- **경계:** DMZ
- **외부:** 인터넷망, 기관 간 연계망(대외망), 공공 클라우드 인터넷 영역, 민간 클라우드

클라우드는 등급이 아니라 망 종류로 다룬다. 같은 클라우드라도 업무 영역은 내부, 인터넷 영역은 외부다. 그래서 "GCloud 인터넷망"은 외부가 된다.

#### 1-2. 연결 규칙

두 망 사이에 보통 필요한 연결 방식을 정한다. 방식은 세 가지다.
- **방화벽(또는 VPN)으로 됨**
- **망연계 필요**
- **보통 잇지 않음(예외 확인)**

**기본 규칙은 등급 짝 단위다. (제 판단)**

| 짝 | 보통 필요한 방식 |
|---|---|
| 내부 ↔ 외부 | 망연계 필요 |
| 내부 ↔ 경계 | 방화벽 |
| 경계 ↔ 외부 | 방화벽 |
| 같은 등급끼리(다른 망) | 방화벽 |
| 폐쇄 ↔ 어느 쪽이든 | 보통 잇지 않음 |

**사용자 규칙은 망 종류 짝 단위로 넣는다.** 예: "행정망 ↔ 공공 클라우드 내부 영역: 망연계 필요". 사용자 규칙에는 한 줄 근거를 적을 수 있다. 예: "○○기관 망 운영 지침 3조".

**우선순위.** 사용자 망 종류 짝 규칙 > 기본 등급 짝 규칙.

#### 1-3. 망 지식 화면

- 용어 사전 화면과 같은 셸과 같은 모양을 쓴다. 사이드바와 접힌 레일에 "망 지식" 항목을 더한다. **(제 판단)**
- 화면은 두 부분이다.
  - **망 종류 목록:** 더하기, 고치기, 지우기
  - **연결 규칙 표:** 기본 등급 규칙 보기, 망 종류 짝 규칙 더하기·고치기·지우기
- **기본 제공 항목. (제 판단)**
  - 고칠 수 있다. 고치면 "사용자가 고침"이 되고, "기본값으로 되돌리기"가 있다.
  - 지울 수는 없고 "쓰지 않음"으로 숨긴다. 다음 업데이트에서 기본 항목이 다시 생기지 않게 하려는 것이다.
- **사용 중인 망 종류를 지우면. (제 판단)** 그 종류를 쓰던 망 영역들은 종류가 비게 되고, "채워야 할 정보"로 센다. 지우기 전에 "구성도 N곳의 망이 이 종류를 써요"라고 알린다.
- 기본 등급 규칙 자체를 고치는 화면은 이번에 두지 않는다. 기관 규칙은 망 종류 짝 규칙으로 덮어쓴다. **(제 판단)**

### 2. 망 영역에 종류 붙이기

- 망 영역마다 망 종류(1-1의 항목 하나)를 붙인다. 비어 있으면 모름이다.
- **AI가 추정해서 붙이고 사용자가 확인한다. (사용자)**
  - AI는 망 이름과 대화 맥락을 보고 망 지식의 이름과 다른 이름 목록에서 고른다.
  - 맞는 항목이 없거나 근거가 없으면 비워 둔다. AI가 새 망 종류를 만들지는 않는다.
  - AI 프롬프트에는 망 종류 목록(이름, 다른 이름, 등급)이 들어간다.
- AI가 붙인 종류에는 "AI 추정" 표시가 달린다. 사용자가 "맞아요"를 누르면 표시가 사라지고, 목록에서 다른 종류로 바꿀 수도 있다. 사용자가 직접 정한 종류에는 표시가 없다.
- **이미 그려진 구성도. (사용자)** 지금 있는 망 영역은 모두 종류가 비어 있다. 다음 대화 차례에 AI가 구성 변경과 함께 기존 망의 종류도 추정해 붙인다. 따로 AI를 부르지 않는다. 대화를 한 번도 하지 않으면 "채워야 할 정보"에서 손으로 채운다.
- 종류가 비어 있는 망은 "채워야 할 정보"로 센다. 단, 구성도에 망이 둘 이상 있을 때만 센다. **(제 판단)** 망이 하나뿐이면 넘나들 곳이 없기 때문이다.
- **확인과 변경은 두 곳에서 한다. (제 판단)** 영역을 고르는 화면이 지금은 없어서 새로 만들지 않는다.
  1. "채워야 할 정보" 목록(`MissingChecklist`)에 망 종류 줄을 둔다. 지금은 노드·연결만 다루므로 망 영역까지 넓힌다.
  2. 아래 "연결 방식 예상" 안내 카드 안에도 둔다. 예: "행정망을 '행정망(내부)'으로 추정했어요 [맞아요] [바꾸기]".

### 3. 고려가 시작되는 시점

- **망에 종류가 붙는 순간부터 고려한다. (사용자)** 종류가 없는 망끼리는 지금과 똑같이 그린다. 예상 안내도 없고 AI가 망연계를 넣지도 않는다.
- AI가 추정한 종류여도 고려를 시작한다. **(제 판단)** 확인을 기다리면 행정망 사례 같은 안내가 늦어진다. 대신 안내 문구에 추정이라는 점을 함께 적는다.
- 망 지식을 고치면, 그 계정의 구성도를 다음에 열거나 다음 차례가 끝날 때 새 지식으로 다시 판정한다. **(제 판단)**

### 4. 연결 방식 예상 (안내)

**통신 길.** 경계 노드(방화벽·망연계·VPN)만을 사이에 두고 이어진 연결 묶음이다. 예: PC → 방화벽 → WAS 는 연결 둘이지만 길은 하나다. 길의 양 끝은 경계 노드가 아닌 노드다.

**판정.** 양 끝이 서로 다른 망 영역에 있고 두 망 모두 종류가 있으면, 1-2의 규칙으로 필요한 방식을 정해 길과 견준다.

| 필요한 방식 | 길의 모습 | 결과 |
|---|---|---|
| 망연계 필요 | 망연계 노드가 하나도 없음(방화벽·VPN만, 또는 경계 노드 없음) | **"망연계 필요 예상"** |
| 보통 잇지 않음 | 어떤 모습이든 | **"보통 잇지 않는 구간"** |
| 방화벽 | 경계 노드 없음 | 기존 `network_direct` 경고 |
| 그 밖 | | 표시 없음 |

- 경계 노드 없이 바로 이어진 길이면, 위 결과에 더해 기존 `network_direct` 경고도 그대로 함께 뜬다.
- **망 영역 밖 노드는 판정에서 뺀다. (사용자)** 대신 AI 프롬프트에 규칙을 둔다. 구성도에 종류가 붙은 망이 있으면, 인터넷 쪽 서버(클라우드 WAS 등)는 알맞은 망 영역 안에 그린다. 외부 사용자와 외부 SaaS처럼 원래 망 밖에 그리는 것은 그대로 둔다.

**안내 모양. (제 판단)**
- 기존 경고 목록에 새 규칙으로 들어간다. 이름은 만드는 사람이 정한다.
- 단계는 `check`다. 경고(`warn`)가 아니라 확인 권고다.
- 평소 캔버스 표시는 기존 경고·망 넘음 표시 방식을 따른다.

**문구는 단정하지 않는다. (사용자)**
- 근거가 어디서 왔는지 밝힌다.
  - 기본 규칙이면: "보통 내부망과 인터넷 쪽 망 사이는 방화벽 허용만으로는 통신할 수 없고 망연계가 필요해요. 기관 규정과 방화벽 담당자에게 확인해 보세요."
  - 사용자 규칙이면: "등록한 기관 규칙(○○기관 망 운영 지침 3조)에 따르면 망연계가 필요해요."
- 종류가 AI 추정이면 앞에 "행정망을 '행정망(내부)'으로 추정했어요." 를 붙인다.
- 망연계를 넣고 싶으면 대화로 "망연계 넣어 줘"라고 하면 된다는 안내를 한 줄 붙인다. 따로 "망연계 넣기" 단추는 두지 않는다. **(제 판단)** AI가 직접 넣는 길(아래 5)과 겹친다.

**흐름.** 흐름의 한 단계가 이런 길을 지나면, 그 단계 설명에 이미 붙는 "망을 넘어감" 설명 뒤에 같은 예상이 짧게 붙는다.

### 5. AI가 망연계를 넣어 그리기

- 종류가 붙은 뒤에 AI가 구성을 그리거나 고치면서 "망연계 필요"인 두 망을 잇게 되면, **망연계 노드를 넣어 그린다. (사용자: "미리 그려 주는 서비스")**
  - AI 프롬프트에 망마다 종류와, 그 구성도에 있는 망 짝들의 필요한 방식을 넣는다.
  - "보통 잇지 않음"인 짝은 AI가 사용자 요청대로 그리되, 그 차례 답에서 한 줄로 알린다. 그리고 4의 안내가 뜬다.
  - 사용자가 대화로 "방화벽으로 바로 열어" 처럼 직접 정하면 AI는 그대로 따른다. 이때 망연계는 넣지 않고 4의 안내만 남는다.
    - 이 지시도 6의 거절 기억과 같은 가정으로 남긴다(AI가 그 차례에 가정 명령을 함께 쓴다). 그래야 다음 차례에 AI가 같은 자리에 망연계를 다시 넣지 않는다. 다만 "아니에요"와 달리 안내는 끄지 않는다. 사용자가 규정을 확인하도록 남겨 둔다. **(제 판단)**
- **흐름. (제 판단)** AI가 기존 길에 망연계를 끼워 넣으면, 그 연결을 지나던 흐름 단계를 도구가 정해진 규칙으로 둘로 나눈다. 예: "방화벽 → WAS" 한 단계가 "방화벽 → 망연계, 망연계 → WAS" 두 단계가 된다. 나눈 두 단계의 설명은 원래 단계 설명을 쓴다. 6의 되돌리기와 짝을 이룬다.
- **"AI 추정" 표시. (사용자)** AI가 스스로 판단해 넣은 망연계 노드에는 "AI 추정" 표시와 **맞아요 / 아니에요** 단추가 붙는다.
  - 사용자가 대화로 망연계를 넣어 달라고 해서 들어간 노드에는 붙지 않는다.
  - 어느 경우가 "스스로 판단"인지 가르는 방법은 만드는 사람이 정한다. 예: AI 명령에 추정 표시를 따로 쓰게 함.
- **맞아요**를 누르면 표시가 사라지고 일반 노드가 된다.

### 6. "아니에요" — 되돌리기

**직전 상태를 미리 저장해 두고 되돌린다. (사용자)**

**저장.** AI가 망연계 노드를 추정으로 넣는 순간, 그 노드가 대신한 연결들을 노드에 붙여 저장한다.
- 예: PC → 방화벽 → WAS 의 "방화벽 → WAS" 연결을 저장한다.
- 연결의 종류, 이름, 전달물, 방향을 모두 그대로 저장한다.
- 새로 그리는 중이라 대신한 연결이 없으면, 저장할 것은 "망연계 앞 노드와 뒤 노드를 바로 잇는다"는 사실과 그 연결 속성이다. 속성은 망연계로 들어가는 연결의 것을 쓴다.

**되돌리기. (사용자: "다른 구성도를 망가뜨리지 않고")**
- 대상은 그 망연계 노드, AI가 함께 만든 앞뒤 연결, 저장해 둔 연결뿐이다. 그 노드를 지우고 저장한 연결을 되살린다.
- 다른 노드·연결·영역·흐름은 건드리지 않는다.
- AI를 다시 부르지 않고 도구가 정해진 규칙으로 처리한다.
- 일반 구성 변경처럼 버전으로 남으므로 이력에서 다시 되돌릴 수 있다.
- 흐름은 앞선 문서대로 버전 밖(`flows` 테이블)에 저장된다. 그래서 이력에서 버전을 되돌릴 때 흐름은 따라가지 않는다. 그때 맞지 않게 된 단계는 기존 규칙대로 "끊김"과 "다시 맞추기"로 처리한다. 흐름을 버전에 묶는 일은 하지 않는다. **(제 판단)**

**흐름. (제 판단)** 흐름 단계가 그 망연계를 지나고 있었다면, 되살린 연결로 단계를 바꿔 끼운다.
- 예: "방화벽 → 망연계, 망연계 → WAS" 두 단계가 "방화벽 → WAS" 한 단계가 된다.
- 단계 설명은 앞 단계 것을 쓴다.

**주변이 바뀐 경우. (제 판단)** 넣은 뒤에 사용자가 그 노드의 연결을 고쳤거나, 저장한 연결의 양 끝 노드가 사라졌으면 깔끔하게 되돌릴 수 없다.
- 이때는 노드만 지우고, 되살릴 수 있는 연결만 되살린다.
- 그래서 끊긴 흐름은 기존 "끊김" 표시와 "다시 맞추기"로 넘긴다.
- 그렇게 된다는 걸 한 줄로 알린다. 예: "주변 연결이 바뀌어 일부만 되돌렸어요."

**거절 기억. (사용자)** "아니에요"를 누른 구간(두 망 영역의 짝)은 기억한다.
- 기존 가정(`set_assumption`)에 한 줄로 남긴다. 예: "행정망 ↔ GCloud 인터넷망: 망연계 없이 통신(사용자 확인)". 가정은 AI 프롬프트에 이미 들어가므로, AI가 같은 자리에 다시 넣지 않는다. **(제 판단)**
- 그 구간의 "망연계 필요 예상" 안내도 끈다.
- 끄는 단위는 **두 망 영역의 짝**이다. 같은 두 망 사이에 길이 여럿이거나 나중에 새 길이 생겨도 함께 꺼진다. 그래서 이 안내의 id는 연결이 아니라 망 짝 기준으로 만든다. 기존 `ignoredWarnings`는 그 id로 쓴다. **(제 판단)**
- 이 기억은 그 구성도 안에서만 쓴다. 망 지식(모든 프로젝트 공통)을 바꾸지는 않는다. 기관 전체 규칙으로 삼고 싶으면 사용자가 망 지식 화면에서 규칙을 더한다. **(제 판단)**

### 7. 종류나 지식이 나중에 바뀌면 (제 판단)

- 망 종류를 바꾸거나 지우거나 망 지식 규칙을 고쳐서 필요한 방식이 달라지면, 예상 안내는 새 판정을 따른다.
- 이미 그려진 망연계 노드는 지우지 않는다. 몰래 구성을 바꾸지 않는다는 기존 원칙 때문이다. "AI 추정" 표시가 남아 있으면 그대로 두어 사용자가 고르게 한다.
- 거절 기억(가정)은 남긴다. 사용자가 대화나 가정 칩에서 지울 수 있다.

## 하지 않는 것

- 기관 내부 규정을 스스로 알거나 판정하지 않는다. 늘 "예상"이며, 기관 규칙은 사용자가 넣는다.
- 규정 문서를 올려 AI가 규칙을 뽑는 일은 하지 않는다. 문서 읽기 프로젝트(C)에서 붙인다.
- 망 지식을 파일(엑셀·JSON)로 올리거나 내려받는 일은 하지 않는다.
- 팀·기관 단위 망 지식 공유는 하지 않는다. 계정 단위다.
- 기본 등급 규칙 자체를 고치는 화면은 두지 않는다.
- 방화벽 정책표 생성은 다음 프로젝트(B)다.
- 영역을 고르는 화면이나 영역 정보 패널은 새로 만들지 않는다.

## 실패로 보는 것

- 행정망 PC → 방화벽 → GCloud WAS 같은 그림이 종류가 붙었는데도 아무 안내 없이 통과한다.
- 안내가 단정적이라 사용자가 규정 확인 없이 그대로 믿는다. 또는 기본 규칙과 기관 규칙 중 어느 쪽 근거인지 알 수 없다.
- 망 지식에 넣은 기관 규칙이 다른 프로젝트 구성도에는 반영되지 않는다.
- "아니에요"를 눌렀더니 그 망연계와 상관없는 노드·연결·흐름이 바뀐다.
- 거절한 자리에 다음 대화에서 AI가 망연계를 또 넣는다.
- AI 표시(AI 설명·AI 제안·AI 추정)가 여기저기 붙어 평소 화면이 어지러워진다.
- 망 종류 추정 때문에 구성 그리기 차례가 눈에 띄게 느려진다.
- 망 지식 화면이 용어 사전과 다른 조작 방식이라 처음 보는 사람이 헤맨다.

## 제약

- **앞선 문서의 제약을 그대로 따른다.**
  - 명령 흐름: JSONL → 검증 → 적용 → 버전
  - Qwen: 출력 16k, 이어 쓰기 2번, 240초
  - 1단계 화면 규칙: 토큰 색, LIGHT_TOKENS 짝, 움직임 줄이기, stacking, Tab+화살표, 24px, 쉬운 한국어
  - drizzle 마이그레이션: 개발 DB 적용과 푸시는 사용자가 요청할 때만
  - 문서 사이트 동기화
  - 배치 측정 회귀
- **AI 표시 통일. (제 판단, 사용자에게 추천해 승인받음)**
  - 새로 생기는 두 표시(망 종류, 망연계 노드)는 기존 "AI 설명"·"AI 제안" 배지(`src/ui/glossary/aiBadge.ts`)와 같은 모양과 같은 화면 읽기 문구를 쓴다. 글자는 "AI 추정"이다.
  - 확인 단추는 늘 "맞아요 / 아니에요" 한 쌍이다.
  - 이미 있는 "AI 설명"·"AI 제안" 글자는 바꾸지 않는다.
- **프롬프트 크기.** 망 종류 목록 전체를 넣으면 길어진다. 그래서 이름, 다른 이름, 등급만 넣고 설명은 넣지 않는다. 연결 규칙은 그 구성도에 있는 망 짝에 해당하는 것만 넣는다. **(제 판단)**

## 만드는 사람에게 맡기는 것

- **저장 위치와 이름.**
  - 망 영역의 종류 저장 위치와 이름. 예: `Group` 에 망 종류 key, 출처, 확인 여부.
  - `add_group` 에 칸을 더할지, `update_group` 명령을 새로 둘지. 둘 다 기존 명령 흐름을 따른다.
  - 망 지식 테이블 모양(망 종류, 연결 규칙). 용어 사전처럼 기본 항목(seed)을 넣는 방식도 맡긴다.
- 대신한 연결을 저장할 모양(노드 속성인지 별도 칸인지). 단, 구성도 상태 안에 있어 버전과 함께 저장되어야 한다.
- "통신 길"을 찾는 방법(경계 노드만 거치는 경로 탐색). 갈래와 순환을 막는 처리도 맡긴다.
- 기본 망 종류의 정확한 목록, 다른 이름, 설명 문구. 1-1의 범위를 덮는다.
- 안내·표시의 정확한 캔버스 모양. 1단계 규칙과 "평소엔 작게, 고를 때 자세히" 원칙 안에서 정한다.
- AI 프롬프트 문구, 종류 추정을 구성 차례 안에서 어떻게 쓰게 할지.
- **테스트 구성.**
  - 단위: 판정표, 우선순위, 되돌리기, 흐름 단계 나누기·합치기
  - 통합
  - E2E: 가짜 LLM 응답 사용
  - 고정 시나리오: 행정망 사례, 기관 규칙을 넣었을 때 다른 프로젝트에도 반영되는 사례
