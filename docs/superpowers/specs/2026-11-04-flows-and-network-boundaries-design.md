# 흐름 보기와 망 경계 표시 — 설계

날짜: 2026-11-04 · 상태: 초안 — 검토자 질문·화면 모양 반영, 사용자 승인 전

## 왜 하는가

구성도에서 **실제 사용자 행위에서 시작하는 흐름**과 **네트워크(시스템) 흐름**을 눈으로 따라갈 수 있게 한다. 사용자가 말한 목적 그대로다.

보는 사람은 둘이다.
- **개발자**: 영향 범위를 본다. 이 행동에 어떤 서버·외부 서비스·DB가 관여하는지, 어떤 노드가 멈추면 어떤 행동이 막히는지를 확인한다.
- **비전문가**: 설명을 듣고 어느 정도 이해하면 된다. 단계마다 쉬운 말 설명이 붙는다.

사용자가 든 예는 둘이다.
- **회원가입.** 브라우저에서 WAS를 거쳐 회원 정보가 DB에 적재되는 일련의 흐름이 보여야 한다.
- **망 분리 환경.** 업무망과 인터넷망이 분리되어 있다.
  - 망연계 솔루션으로 API를 연동하거나, 방화벽 허용으로 직접 통신한다.
  - 그 사이로 API와 파일이 단방향 또는 양방향으로 오간다.

이 작업은 원래 '배치 조화' 2~4단계보다 먼저 한다. 사용자가 "4번(행동별 경로)과 2번(망 경계)이 좀 필요하다"고 정했다. 외부 서비스 배치(원래 2단계)와 같은 망 안 WAS 간 통신·MSA 표현, 사양 검증은 이번 범위가 아니다.

## 이미 있는 것

- **구성도 상태** (`src/domain/types.ts`): groups, nodes, edges, assumptions, warnings. 버전으로 저장된다(`server/versions.ts`).
- **변경 명령** (`src/domain/commands.ts`): add/update/remove_node·edge·group, set_assumption. AI가 JSONL 명령을 쓰고 파이프라인이 적용한다(`server/chat/pipeline.ts`).
- **영역 종류**: cloud_region, vpc, subnet_public, subnet_private, dmz, idc, onprem_zone, k8s_cluster, external_service, redundancy_group.
- **노드 종류**: firewall, vpn, api_gateway 등은 있다. 망연계 솔루션은 없다.
- **연결 종류**: request, async, replication, aux. 연결 이름(label)이 있다. 방향·전달물(API/파일) 속성은 없다.
- **선택 강조** (1단계): 이어진 선 겹선·빛, 나머지 흐림, `emphasis.ts`·`EdgeLayer.tsx`. 흐름 표시 움직임(`motion.ts`)은 묶음 단위로 시간을 맞춘다.
- **설명** (`server/explain.ts`, `explanations` 테이블): 노드·연결 설명을 AI가 따로 만들고 signature로 캐시한다.
- **경고 규칙** (`domain/warnings.ts`): 예를 들어 `no_firewall`(방화벽 없이 바로 들어옴).

## 목표

### A. 흐름

1. **흐름 데이터.** 흐름 하나는 다음으로 이루어진다.
   - 이름. 예: "회원가입"
   - 출발 종류: **사용자 행동** 또는 **시스템·네트워크**
   - 짧은 설명
   - 단계 목록. 단계 하나는 연결 하나와 그 연결을 지나는 방향, 쉬운 말 설명 한 줄이다.
   - 단계는 **가는 길(요청)만** 번호를 붙인다. 응답(DB → WAS → 브라우저)은 단계로 두지 않고 마지막에 "결과가 돌아옴" 한 줄 설명으로 적는다(사용자 선택).
   - 흐름마다 **확인 여부**를 둔다. AI가 만든 흐름은 사용자가 "맞아요"를 누르기 전까지 "AI 제안" 표시가 붙는다(사용자 선택, 지금의 "AI 설명" 표시와 같은 방식).
2. **세 가지 진입.** 사용자가 셋 다 정했다.
   1. **AI가 미리 제안.** AI가 그 구성에서 중요한 흐름 3~5개를 만들어 둔다. 사용자 행동 흐름과 시스템·네트워크 흐름을 모두 포함한다.
      - 시점(사용자 선택): 흐름이 하나도 없는 구성도를 처음 그린 차례가 끝나면 자동으로 한 번. 그 밖(샘플·불러온 구성도, 나중에 다시)은 흐름 탭의 "흐름 제안받기" 버튼으로.
      - 구성 그리기 차례와 따로 요청한다(설명 생성처럼). 그리기 차례를 느리게 하지 않는다.
   2. **대화로 더하기·고치기.**
      - 예: "비밀번호 찾기 흐름도 만들어 줘", "가입할 때 휴대폰 인증도 거쳐".
      - 노드를 언급(@)하고 물어도 된다. 예: "@WAS 가 관여하는 흐름 보여 줘".
      - **구성과 흐름을 한 차례에 같이 바꾼다**(사용자 선택). "가입할 때 휴대폰 인증도 거쳐"면 AI가 노드·연결 추가 명령과 흐름 수정 명령을 같은 차례에 쓴다. 그래서 구성 변경 차례의 프롬프트에 지금 흐름 목록(이름과 단계)이 들어간다.
      - 흐름을 언급하지 않은 구성 변경으로 흐름이 끊기면, AI가 몰래 고치지 않는다. "끊김" 표시와 "흐름 다시 맞추기" 단추만 보인다.
   3. **노드에서 거꾸로.** 노드나 연결을 고르면 정보 카드에 "이 노드를 지나는 흐름: 회원가입 · 로그인 · 결제"가 나오고, 누르면 그 흐름으로 간다.
3. **흐름 보기.** 목록에서 흐름을 고르면 구성도에 다음이 보인다.
   - 지나가는 노드와 연결만 1단계 강조 방식(겹선·빛, 나머지 흐림)으로 드러난다.
   - 연결마다 **단계 번호**(①②③…)가 붙는다.
   - 단계 목록은 오른쪽 패널에 쉬운 말 설명과 함께 나온다. 단계를 누르면 그 연결이 따로 도드라진다.
   - 흐름 표시 움직임이 켜져 있으면 흐름 순서대로 흐른다(1단계 motion 재사용).
4. **흐름 목록.** 구성도마다 "흐름" 목록이 있고, "사용자 행동"과 "시스템·네트워크" 두 묶음으로 나눈다.
   - 이름 바꾸기와 삭제가 된다. 구성도 대화의 세션 목록(RowMenu·dialogs)과 같은 방식이다.
   - 목록은 **오른쪽 패널의 새 "흐름" 탭**에 둔다(사용자 선택). 대화·설명·이력 탭 옆이고, 휴대폰에서는 아래 탭 줄에 들어간다. 흐름을 고르면 같은 탭에서 단계 목록과 설명이 보인다.
5. **끊긴 흐름.** 구성이 바뀌어 흐름의 연결이나 노드가 사라지면 그 흐름을 "끊김"으로 표시한다. 고칠 길을 함께 보인다: 대화로 다시 맞추기, 또는 단계 삭제.
6. **이미지 내보내기.** 이번에는 넣지 않는다(사용자 선택). 지금처럼 평상시 모습만 내보낸다.
7. **기계 검사.** 흐름을 저장하거나 불러올 때 단계의 연결이 실제로 있는지, 단계가 끊김 없이 이어지는지(앞 단계의 도착 노드 = 다음 단계의 출발 노드, 갈래는 허용 규칙을 만드는 사람이 정함) 검사한다. 걸리면 저장을 거절하거나(AI 명령) "끊김"으로 표시한다(구성 변경 뒤).

### B. 망 경계

1. **망 영역.** "업무망", "인터넷망"처럼 분리된 망을 영역으로 나눈다.
2. **망연계 노드.** 망연계 솔루션 노드 종류를 새로 둔다. 방화벽·VPN은 이미 있다.
   - **망을 넘는 통신은 방화벽·망연계·VPN 노드를 거치게 그린다**(사용자 선택). "방화벽 허용으로 직접 통신"도 길에 방화벽 노드를 둔다. 연결에 "거침" 속성을 따로 두지 않는다.
3. **연결 속성.** 연결에 다음을 둔다.
   - **전달물**: API 또는 파일
   - **방향**: 단방향 또는 양방향
   - 화면에 보이는 모양은 아래 B-4를 따른다.
4. **경계 표시.** 서로 다른 망 영역의 노드를 잇는 연결은 망 경계를 넘는 지점에 표시가 붙는다.
   - 경계를 넘는 곳은 경계 노드(방화벽·망연계·VPN)로 들고 나는 연결이다. 그 연결에 전달물과 방향을 짧게 보여 준다. 예: `API ↔`, `파일 →`.
   - 표시가 늘 보일지, 고를 때만 보일지, 모양은 어떤지는 브라우저 비교 화면으로 사용자가 고른다(실패 기준: 평소 화면을 어지럽히면 안 됨).
5. **경고.** 서로 다른 망의 노드가 경계 노드(망연계·방화벽·VPN) 없이 바로 이어져 있으면 경고를 띄운다. 기존 `no_firewall`과 같은 성격이다.
   - 경계를 넘는 연결에 전달물이나 방향이 비어 있으면 "채워야 할 정보"로 센다(제 판단). 그래서 빠진 정보 계산과 입력 폼이 연결 속성까지 넓어진다.
6. **흐름과 함께.** 흐름의 한 단계가 망 경계를 넘으면, 그 단계 설명에 "여기서 업무망 → 인터넷망으로 넘어감, 망연계를 거침"이 자동으로 들어간다.

## 하지 않는 것

- API 명세 전체(엔드포인트·요청·응답 스키마)를 그리지 않는다. 흐름은 "어느 연결을 어떤 순서로"까지만 다룬다.
- 같은 망 안 서비스 간 통신 구조와 MSA 전용 표현은 하지 않는다. 지금 있는 노드와 연결로 그린다.
- 사양·용량 검증, 부하 계산은 하지 않는다.
- 외부 서비스 배치 개선(원래 2단계), 배치 모양과 규모 대응(3·4단계)은 하지 않는다.
- 망연계 승인 절차, 연계 주기 관리 같은 운영 업무 관리는 하지 않는다. 필요한 값은 연결 속성(텍스트)으로만 적는다.

## 실패로 보는 것

- 흐름을 골라도 어느 순서로 지나가는지 헷갈린다. 번호와 선이 따로 놀거나, 번호끼리 겹친다.
- 비전문가가 단계 설명을 읽어도 무슨 일이 일어나는지 모른다(전문용어 덩어리).
- AI가 만든 흐름이 구성도에 없는 연결을 가리키거나, 그럴듯하지만 틀린 경로를 만든다. 사용자가 이를 알아챌 길이 없다.
- 구성이 바뀌어 흐름이 끊겼는데 조용히 틀린 모습을 보여 준다.
- 망 경계 표시가 평소 화면을 어지럽힌다. 1단계에서 정리한 가독성이 나빠진다.
- 흐름 제안 때문에 구성도 그리는 차례가 눈에 띄게 느려지거나 실패한다.

## 제약

- **명령 흐름.** 기존 명령·파이프라인 방식(AI가 JSONL 명령 → 검증 → 적용 → 버전 저장)을 따른다. 흐름을 바꾸는 명령도 같은 길로 다닌다.
- **모델.** Qwen 출력 상한은 16k 토큰이다. 이어 쓰기는 최대 2번, 240초까지다. 자동 흐름 제안은 구성 그리기와 같은 차례에 넣지 않는다. 다만 사용자가 대화로 흐름을 고치라고 하면 그 차례에 흐름 명령도 쓴다(위 A-2).
- **화면 규칙.** 1단계 규칙을 지킨다.
  - 토큰 색만 쓰고, LIGHT_TOKENS 짝을 둔다.
  - 내보내기는 평상시 모습이다.
  - 움직임 줄이기 설정을 따른다.
  - 쌓는 순서는 stacking.ts를 따른다.
  - Tab 한 번 + 화살표로 다닌다.
  - 누르는 자리는 24px 이상이다.
  - 쉬운 한국어를 쓴다.
- **데이터베이스.** 마이그레이션이 필요하면 drizzle 마이그레이션을 쓴다. 개발 DB 적용과 푸시는 사용자가 요청할 때만 한다.
- **문서.** 문서 사이트 동기화 규칙(architecture.md의 명령 표와 데이터 모델)을 따른다.
- **측정.** 1단계 배치 측정 회귀 테스트가 나빠지지 않아야 한다.

## 사용자가 정한 것(설계 검토 뒤)

- 구성과 흐름은 한 차례에 같이 바꾼다. 흐름을 언급하지 않은 변경으로 끊기면 "끊김" + "다시 맞추기"만.
- 흐름은 구성도와 **따로 저장**한다(설명처럼). 흐름 추가·이름 바꾸기가 버전 기록을 늘리지 않는다. 예전 버전으로 되돌려도 흐름은 그대로 두고, 없는 연결을 가리키는 단계만 "끊김"이 된다.
- 망을 넘는 통신은 방화벽·망연계·VPN 노드를 거치게 그린다.
- AI가 만든 흐름은 기계 검사 + "AI 제안" 표시(사용자가 "맞아요"를 누르면 사라짐).
- 흐름 목록은 오른쪽 패널의 새 "흐름" 탭.
- 단계는 요청 방향만, 응답은 마지막 한 줄.
- 자동 제안은 흐름이 없는 구성도를 처음 그린 뒤 한 번 + "흐름 제안받기" 버튼.
- 흐름 상태로 이미지 내보내기는 이번에 넣지 않는다.

## 제가 정한 것

- **흐름 명령.** `add_flow`, `update_flow`, `remove_flow`를 둔다. 같은 JSONL 명령 흐름을 타지만 구성도 상태가 아니라 흐름 저장소에 적용된다. 요약의 "바꾼 곳"에 세지 않는다.
- **흐름 저장.** 구성도마다 흐름 행을 둔다(새 테이블, drizzle 마이그레이션). 단계는 연결 id와 지나는 방향, 설명을 담는다.
- **방향의 뜻.** 연결의 `direction`은 데이터가 흐르는 방향이다. `one_way`면 from → to로만 데이터가 간다. 흐름 단계가 단방향 연결을 거꾸로 지나면 기계 검사에서 걸린다.
- **망 영역.** 새 영역 종류 하나(`network_zone`, "망")에 이름을 붙여 쓴다. 예: "업무망", "인터넷망".
- **망연계 노드 종류.** 새 노드 종류 `network_link`("망연계 솔루션"), 범주 network, 필수 속성은 솔루션 이름.
- **연결 속성.** 연결에 `payload`(api|file)와 `direction`(one_way|two_way)을 선택 속성으로 더한다.
- **경계를 넘는다는 판정.** 두 끝 노드의 가장 가까운 `network_zone` 조상이 다르면 경계를 넘는다. 경계 노드(firewall·network_link·vpn)는 어느 망에 있든, 망 밖에 있든 된다. 망 영역이 없는 구성도에는 경계 표시가 나오지 않는다.
- **빈 값.** 경계를 넘는 연결의 전달물·방향이 비면 "채워야 할 정보"로 센다.

## 화면 모양(사용자 선택, 브라우저 비교 화면)

- **단계 번호: "번호 + 짧은 설명을 캔버스에 바로"**(C안). 흐름을 고르면 각 단계 연결 위에 `4. 인증 요청`처럼 번호와 짧은 설명이 함께 쓰인다. 비전문가가 캔버스만 보고도 따라갈 수 있게.
  - 글자는 1단계 이름 규칙을 따른다: 캔버스색 테두리(halo), 서로·노드·선택 테두리와 겹치지 않게 줄 바꿈·밀어내기(`edgeLabels.ts` 배치 재사용).
  - 짧은 설명은 캔버스용으로 짧게(한 줄, 약 12자 이내). 긴 설명은 흐름 탭의 단계 목록에.
  - 고른 흐름의 단계 글자가 보이는 동안 같은 연결의 일반 연결 이름은 숨긴다(같은 자리 두 글자 방지, 제 판단).
  - 단계가 많아 글자가 겹칠 수밖에 없으면 번호만 남기고 설명은 흐름 탭으로 보낸다(제 판단).
- **망 경계 표시: "평소엔 작게, 고를 때 자세히".** 평소 화면에는 경계를 넘는 연결 위에 작은 금색 점 하나만. 흐름을 보거나 그 연결·노드를 고르면 "망 넘음" 표시와 `API ↔`·`파일 →` 같은 전달물·방향이 나온다.

## 만드는 사람에게 맡기는 것

- 흐름·단계 데이터의 정확한 모양과 이름. 위 「제가 정한 것」을 지키는 범위에서 정한다.
- AI 프롬프트의 문구와 출력 형식. 기존 명령 JSONL 방식을 따른다.
- 단계 번호를 연결의 어느 지점에 놓을지. 1단계의 이름 겹침 규칙(서로·노드와 겹치지 않음)을 지킨다.
- 끊긴 흐름을 판정하는 시점(불러올 때, 구성이 바뀐 차례 뒤 등).
- 테스트 구성: 단위, 통합, E2E(가짜 LLM 응답 포함).
