- 작성일: 2026-10-29
- 상태: 승인됨 (2026-10-29)
- 표기: **[사용자 결정]** = 사용자가 직접 정한 것, **[설계자 판단]** = 대화 중 제안했고 사용자가 이의 없었던 것 또는 문서 작성자가 정한 것

## 1. 의도와 이유

### 1.1 이런 순간을 위해 만든다
1. **운영 중인 서비스 유지보수에 처음 투입될 때** — 코드·구성도가 흩어져 있거나 없어서 전체 그림을 잡기 어렵다. 아는 만큼 대화로 설명하면 AI 가 구성도로 정리해 준다.
2. **새 서비스를 개발할 때** — 코드 전에 인프라 큰 틀(서버·DB·캐시·외부 연동 등)을 먼저 잡고 싶다. "결제·카카오 로그인 붙는 쇼핑몰" 같이 말하면 초안을 그려 주고 대화로 다듬는다.

### 1.2 누구를 위한 것인가
- 지금: 사용자 본인 1명 (개인 도구). **[사용자 결정]**
- 나중: 팀 공유. 지금 구현하지 않지만, 로그인·공유를 나중에 붙이기 쉬운 구조여야 한다.
- 결과물(구성도와 설명)은 **비전공자도 이해**할 수 있어야 한다.

### 1.3 성공의 모습
- 대화 몇 마디로 그럴듯한 구성도가 **노드가 하나씩 나타나며 연결되는** 모습으로 그려진다.
- 노드를 누르면 "이게 뭔지 / 여기서 뭘 하는지 / 왜 골랐는지 / 누구랑 연결됐는지" 를 **짧고 명확하게** 바로 안다.
- 빠진 정보(스펙·IP·hostname·VIP·방화벽 등)를 도구가 먼저 알려 주고 채우도록 이끈다.

## 2. 목표 / 비목표 / 반목표

### 2.1 목표
- 대화형 구성도 생성·수정 (생성: Qwen `qwen3.8-flash-next`, 판정: Clef-Flash)
- 실시간(스트리밍) 렌더링: 노드가 하나씩 나타나고 연결선이 그어짐
- 연결 애니메이션 등 시각화 요소 (빠지면 안 됨) **[사용자 결정]**
- 노드/연결 설명 패널 (정의·역할·ADR·스펙·연관관계·연결 노드 링크, 용어 풀이)
- 영역(VPC/서브넷 등) 및 외부 서비스 묶음 표현
- 서버 상세 정보(스펙·OS·IP·hostname·VIP·방화벽) 와 빠진 정보 알림·가이드
- 표준 구성 패턴 지식 + 이상한 구성 경고
- 프로젝트별 관리: 구성도 여러 장, 대화 기록, 변경 이력

### 2.2 비목표 (이번 범위 아님, 나중을 위해 열어둠)
- 코드 저장소 / docker-compose / 클라우드 설정을 읽어 자동으로 그리기 **[사용자 결정: 나중]**
- 팀 공유·권한, 사내 Nexus 로그인 연동 **[사용자 결정: 나중]** (간단한 회원가입/로그인은 이번 범위, §10.2)
- 실제 인프라 배포(IaC 생성 등), 실시간 모니터링 연동

### 2.3 반목표 — 이렇게 되면 기능이 다 돼도 실패 **[사용자 결정]**
1. **설명이 길고 어려워 장황해지는 것.**
2. **캔버스가 엉켜** 노드 간 연결이 복잡해지고, 노드 안 글자를 알아볼 수 없게 되는 것.
3. (추가, 사용자 언급) 노드를 자유 드래그로 편집하게 만들어 조작이 복잡해지는 것.

- **오른쪽**: 탭 패널 하나를 대화/설명이 공유. 캔버스에서 노드·연결선을 선택하면 설명 탭이 자동 활성화. 빈 곳 클릭/대화 탭 클릭으로 대화로 복귀.
- UI 언어: 한국어. 기술 용어는 원어 병기. **[설계자 판단]**
- **떠 있는 유리 패널** **[사용자 결정, 2026-10-30]**
  - 캔버스가 화면 전체 바탕이다. 사이드바(펼침 240px / 레일 56px)와 오른쪽 패널(너비 320–720)은 사방 12px(`--panel-gap`) 여백을 두고 모서리가 둥근 반투명 판으로 떠 있다. 그림자는 쓰지 않는다.

  - 사이드바 머리의 접기 버튼(`프로젝트 영역 접기`/`프로젝트 영역 펼치기`)으로 아이콘 레일(펼치기·새 프로젝트·용어 사전·계정)로 접는다. 접힘은 브라우저(`infrasketch.sidebarCollapsed`)에 기억하고, 용어 사전 화면도 같은 셸을 쓴다.
  - 캔버스 맞춤은 두 패널 사이의 보이는 띠에 한다. 접거나 너비를 바꿔도 카메라는 그대로이고 다음 맞춤부터 새 폭을 쓴다. 캔버스 도구 모음도 오른쪽 패널 왼쪽에 둔다. 보이는 띠는 360px 이상을 지킨다.

## 4. 구성도 만들기·고치기

### 4.1 기본 원칙 **[사용자 결정]**
- **구조 변경은 대화로만**: 노드/연결 추가·삭제, 이름·스펙 수정은 전부 대화로 AI 가 수행.
- **위치 조정만 편집 모드에서**: "편집 모드" 를 켰을 때만 노드를 끌어 위치를 옮길 수 있다. 평소엔 캔버스가 잠겨 보기 전용(확대/축소/이동은 가능).
- 노드·연결을 수동으로 추가/삭제하는 캔버스 UI 는 만들지 않는다.

### 4.2 자동 배치 **[설계자 판단]**
- LLM 은 좌표를 정하지 않는다. "무엇이 무엇과 어떻게 연결되는지" 만 만든다.
- 배치는 자동 배치 엔진(ELK.js layered)이 계층 순서(사용자 → 진입(LB 등) → 앱 서버 → 데이터)와 중첩 영역을 고려해 결정.
- 편집 모드로 옮긴 위치는 저장되며, 이후 AI 가 구조를 바꿀 때도 가능한 한 유지(고정 노드로 취급)하고 새 노드만 배치한다. 사용자가 "자동 정렬" 버튼으로 다시 전체 배치 가능.

### 4.3 실시간 생성 **[사용자 결정]**
- AI 응답이 오는 동안 변경 명령이 하나 도착할 때마다 캔버스에 반영: 노드는 나타나는 애니메이션, 연결선은 그어지는 애니메이션.
- 대화창에는 진행 상황이 한 줄씩 표시 ("L7 로드밸런서 추가…", "캐시·DB 연결…").
- 완료 시 요약 ("노드 8, 연결 7") 과 함께 연결선의 데이터 흐름 애니메이션 시작.
- 생성 도중 배치가 계속 흔들리지 않도록, 스트리밍 중엔 임시 배치 → 완료 시 최종 배치로 부드럽게 이동하는 방식을 권장. 구체 방식은 구현자 재량.

### 4.4 노드 참조 **[사용자 결정]**
- 모든 노드(와 연결선, 영역)는 고유 ID 를 가진다.
- 노드 우클릭 메뉴 또는 "노드 링크 복사" 버튼 → 대화 입력창에 `@WAS#1` 형태의 참조 칩이 삽입됨.
- 사용자가 "@WAS#1 메모리 32GB 로 올려줘" 라고 하면 AI 는 그 ID 의 노드를 정확히 수정.

### 4.5 생성 모델 연동 (Qwen) **[사용자 결정: qwen3.8-flash-next, 사내 vLLM, OpenAI 호환 API]**
- 모델: `qwen3.8-flash-next`. 대화 응답·구성도 변경 명령·노드 설명 등 **글을 만드는 모든 일**을 맡는다. (초안의 GLM-5.3-Flash 는 사용하지 않음)
- 연결 정보와 호출 규칙은 §10.3.
- AI 는 구성도를 **작은 변경 명령의 연속**으로 출력한다. 명령 예:
  - `add_group`(영역/외부 서비스), `add_node`, `add_edge`, `update_node`, `update_edge`, `remove_node`, `remove_edge`, `set_assumption` (설명은 §6.6 대로 별도 단계에서 생성)
  - `remove_group`: 영역과 그 안의 하위 영역·노드, 그것들에 닿은 연결을 함께 지운다(내부 명령, 사용자 문구 없음). AI 차례가 끝나면 이번 차례에 비게 된 영역(노드도 하위 영역도 없는 영역 중 차례 시작 때는 비어 있지 않던 것)을 안쪽부터 자동으로 지우고, 지운 영역은 `remove_group` 명령으로도 보내 화면과 맞춘다. 환경·배포 방식 가정이 바뀌면 AI 는 ① 새 가정에 맞는 영역을 만들고 ② 계속 쓰는 노드를 `update_node` 의 `parent` 로 새 영역에 옮긴 뒤 ③ 남은 맞지 않는 노드·영역을 지운다(`remove_group` 은 안의 노드까지 지우므로 옮기기가 먼저다). **[사용자 결정, 2026-10-30]**
  - `warn` 은 쓰지 않는다. 경고 판단은 코드 규칙 + Clef, 문구만 Qwen 이 별도 호출로 쓴다(§7.2, §12.1 약점 3). **[사용자 결정, 2026-10-30]**
  - `report_missing` 은 쓰지 않는다. 빠진 정보는 코드가 노드 종류별 필수 항목으로 계산한다(§8). **[사용자 결정, 2026-10-29]**
- 전달 방식 두 가지를 모두 지원 **[설계자 판단, 사용자 동의]**:
  1. **Tool calling (기본)**: 함수 호출로 명령 수신. 사용자 측 에이전트 확인 결과 동작하는 것으로 보이나 서버 플래그는 미확인.
  2. **JSON Lines 폴백**: 한 줄에 명령 하나씩 JSON 으로 출력하게 하고 줄 단위로 파싱.
  - 연결 시 지원 여부를 한 번 자동 확인하고 방식을 고른다. 화면상 동작은 두 방식이 동일.
- 모든 명령은 스키마 검증 후 적용. 잘못된 명령(없는 노드 ID 참조 등)은 버리고 대화창에 조용히 알림 또는 AI 에 재요청.
- 대화 맥락에는 현재 구성도 상태(노드·연결·ID)를 요약해 함께 보낸다.

### 4.5.1 가정 목록 **[사용자 결정: 추가]**
- 요청이 애매해도 AI 는 먼저 초안을 그리되, **구조를 정한 가정**을 함께 내놓는다(`set_assumption` 명령).
  예: "환경: 클라우드(AWS)", "규모: 일 사용자 1만", "이중화: WEB-WAS-DB 각 2대", "DB 복제: 비동기".
- 가정은 대화 탭 상단(빠진 정보 체크리스트 옆)에 칩 목록으로 표시. 칩을 누르면 대안 선택지(예: 클라우드 / IDC / 하이브리드)가 뜨고, 고르면 그 내용으로 AI 가 구성을 다시 조정한다.
- 빠진 정보(§8)는 **속성**(IP·스펙 등), 가정은 **구조 결정**(환경·규모·이중화 방식 등)이다. 둘은 따로 표시한다.
- 사용자가 확정한 가정은 "확정" 표시로 바뀌고, 이후 AI 는 그것을 바꾸지 않는다(사용자가 대화로 요청할 때만).
- 가정 항목(최소): 환경(클라우드 종류/IDC/하이브리드), 규모(사용자 수·트래픽), 이중화 수준, 배포 방식(VM/컨테이너/K8s/서버리스), 데이터 복제 방식, 외부 연동 유무. **[설계자 판단: 항목]**

### 4.6 판정 모델 연동 (Clef-Flash) **[사용자 결정: 역할 3가지]**
Clef-Flash(`Cloudflare/clef-flash`)는 글을 생성하지 않고 질문별 선택지 확률만 돌려주는 **판정 전용** 모델이다. 빠르므로 대화 앞단의 분기·검사에 쓴다.

| 역할 | 질문 유형 | 내용 |
|---|---|---|
| **요청 의도 분류** | `choice` | 사용자 입력을 구조 변경 / 질문·설명 요청 / 빠진 정보 답변 / 되돌리기·이력 / 기타 로 분류 → Qwen 에 보낼 프롬프트·도구 세트를 고른다 |
| **이상 구성 판정** | `noul` | 경고 규칙 중 코드로 확정하기 애매한 항목을 예/아니오로 판정(예: "이 DB 가 외부에서 직접 접근 가능한가"). 경고 문구 자체는 Qwen 이 짧게 작성 |
| **설명 품질 검사** | `score` | 생성된 노드 설명의 비전공자 기준 난이도·장황함 점수. 기준 초과 시 Qwen 에 짧고 쉽게 재작성 요청(§6.5) |

- 패턴 매칭·가이드 대화 판정에는 쓰지 않는다(사용자 미선택).
- 낮은 `confidence` 처리 **[설계자 판단]**: 의도 분류가 애매하면 Qwen 에 일반 프롬프트로 넘긴다. 이상 구성 판정이 애매하면 경고 대신 "확인해 보세요" 수준의 약한 안내.
- 입력 한도 16,384 토큰: 노드 100개 구성 전체를 보내지 말고 판정 대상 노드와 이웃만 `state` 로 보낸다. **[설계자 판단]**
- Clef 장애·429 시 **[설계자 판단]**: 의도 분류는 건너뛰고 Qwen 일반 경로, 이상 구성은 코드 규칙만, 품질 검사는 글자 수 검사만으로 대체. 기능이 멈추지 않는다.
- 연결 정보와 호출 규칙은 §10.4.

## 5. 캔버스 표현

### 5.1 요소
- **노드**: 아이콘 + 이름 + 짧은 부제(SW 이름, 대수 등). 예: `🖥️ API 서버 / Spring ×2`.
- **영역(그룹)**: 우리 서비스 영역(예: AWS VPC, IDC), 그 안의 공개/내부 구역(서브넷, DMZ 등). 중첩 가능.
- **외부 서비스**: 점선 큰 상자(예: 결제대행사, 카카오 로그인). **[사용자 결정]** 내부 구성을 알면 상자 안까지, 모르면 우리와 닿는 접점(결제 승인 API, Webhook, OAuth 서버 등)까지만 그린다.
- **이중화 묶음**: VIP 로 묶인 이중화 쌍(WEB#1/#2, DB Active/Standby 등)을 하나의 묶음 테두리 + VIP 라벨로 표현.
- **연결선**: 방향, 방식 라벨(HTTPS, TCP 6379, Webhook, 복제 등). 의미는 **선 모양**으로 구분한다(§5.2).
- **방화벽**: 구간 사이 방화벽 필요 여부/규칙을 연결선 또는 영역 경계에 표시.

### 5.1.1 노드 종류 목록 (AI 가 쓸 수 있는 어휘) **[사용자 결정: 문서에 명시 / 목록은 설계자 판단]**
AI 는 아래 `kind` 중에서만 노드를 만든다(없는 종류는 `generic` + 사용자 라벨). 종류마다 아이콘·필수 속성(빠진 정보 계산 기준)이 정해진다.

| 분류 | kind | 필수 속성(빠진 정보 대상) |
|---|---|---|
| 사용자/클라이언트 | `client_web`, `client_mobile`, `admin_user` | — |
| 진입·네트워크 | `dns`, `cdn`, `waf`, `firewall`, `lb_l4`, `lb_l7`, `api_gateway`, `nat`, `vpn` | 방화벽·LB: 포트/규칙, VIP |
| 서버 | `web_server`, `was`, `app_server`, `batch_server`, `bastion` | hostname, CPU, RAM, 디스크, OS, IP, SW/버전 |
| 컨테이너 | `k8s_cluster`(그룹), `k8s_ingress`, `k8s_service`, `k8s_pod` | 클러스터: 노드 수·버전, Pod: 레플리카 수 |
| 서버리스 | `function`, `managed_service` | 런타임/서비스명 |
| 데이터 | `db_rdb`, `db_nosql`, `cache`, `search`, `object_storage`, `file_storage`, `db_proxy`(DB 중계) | 스펙, IP, 복제 방식, 버전 |
| 메시징 | `queue`, `stream`(Kafka 등) | 브로커 수, 버전 |
| 운영 | `monitoring`, `logging`, `ci_cd` | SW/버전 |
| 외부 | `external_api`, `external_auth`, `external_pg`(외부 서비스 상자 안 접점) | 연동 방식 |
| 기타 | `generic` | — |

- 그룹 종류(`group_kind`): `cloud_region`, `vpc`, `subnet_public`, `subnet_private`, `dmz`, `idc`, `onprem_zone`, `k8s_cluster`, `external_service`, `redundancy_group`(VIP 이중화 묶음, 2대 이상).
- AZ 는 그룹이 아니라 서브넷·노드의 속성 `az` 로 둔다(§12.1 약점 1).
- 연결 종류(`edge_kind`): `request`(동기), `async`(비동기·이벤트·웹훅), `replication`(복제·동기화), `aux`(관리·모니터링). 모양과 움직임은 §5.2. 연결 속성: 프로토콜, 포트, 방향, 방화벽 필요 여부.
- 목록은 데이터 파일로 관리해 확장 가능. 스파이크 결과(§12)로 조정.

### 5.2 연결선 모양과 애니메이션 **[사용자 결정: 시안 확정 — `.superpowers/brainstorm/*/content/edge-motion.html`]**
의미는 색이 아니라 **선 모양**에 고정한다. 계속 행진하는 점선, 동그란 점이 흐르는 표현은 쓰지 않는다.

| edge_kind | 의미 | 모양 | 평상시 움직임 |
|---|---|---|---|
| `request` | 동기 요청 (호출하고 응답을 기다림) | 가는 실선 1.2px, `edge.request` | **빛 꼬리**: 흐린 긴 꼬리 → 밝은 중간 → `accent` 골드 머리, 3겹 대시가 같은 끝점으로 호출 방향을 지나감 |
| `async` | 비동기·이벤트·웹훅 (보내고 기다리지 않음) | 긴 점선 7/5, `edge.async` | **캡슐 패킷**: 9×4 둥근 캡슐 2개가 선을 따라 회전하며 띄엄띄엄 흐름 |
| `replication` | 복제·동기화 | 가는 이중선 (굵은 선 위에 바탕색 가는 선), `edge.replication` | **광택**: 22px 밝은 구간이 느리게(속도 50%) 미끄러짐 |
| `aux` | 관리·모니터링 (Bastion, Prometheus 등) | 흐린 짧은 점선 1.5/4, `edge.aux` `#56657C` | 없음. 기본 숨김, 연결된 노드를 선택하면 보임 |

- 화살촉은 작은 열린 꺾쇠(채우지 않음), 선과 같은 색.
- **속도**: 모든 선이 같은 화면 속도(초당 약 90px, 비동기 75%, 복제 50%)로 움직인다. 선 길이와 무관하게 속도가 같아야 고급스럽게 보인다.
- **엇갈림**: 선마다 시작 시점을 어긋나게 해 동시에 번쩍이지 않게 한다.
- **갈라지고 합쳐지는 선** **[사용자 요청, 시안: `edge-branch.html`]**: 같은 출발점이나 같은 도착점을 가진 연결은 몸통 구간을 공유한다(ELK 의 연결 병합 결과). 이런 선은 개별로 움직이지 않고 **한 흐름**으로 움직인다.
  - 겹치는 몸통 구간은 선과 움직임을 **한 번만** 그린다. 선이 진해지거나 빛이 두 번 지나가지 않게 한다.
  - **갈라짐**(한 출발점 → 여러 도착점): 몸통을 빛 하나가 지나가고, 갈림점에서 모든 갈래로 동시에 나뉜다.
  - **합쳐짐**(여러 출발점 → 한 도착점): 각 갈래의 빛은 합류점에 동시에 도착하도록 시작 시점을 거꾸로 계산한다. 합류 뒤에는 빛 하나로 이어진다.
  - 갈림점과 합류점에는 작은 점(반지름 약 2px, 선 색)을 찍어 이어짐을 보여준다.
  - 구현: 연결선을 "구간 그래프"(몸통 구간과 갈래 구간)로 쪼개고, 한 묶음은 같은 주기 안에서 구간마다 시작 시각을 오프셋으로 준다. 꼬리 길이만큼 구간끼리 겹쳐 이어져 보이게 한다.
  - `async` 패킷과 `replication` 광택에도 같은 규칙을 적용한다.
- **생성 시**: 노드는 나타나고, 선은 그어지는 애니메이션(§4.3). 다 그린 뒤 평상시 움직임 시작.
- **선택 시**: 선택 노드와 연결된 노드·선만 남기고 나머지는 22% 불투명도로 물러남(0.35초 전환). 선택 노드는 `accent` 바깥 테두리. 숨겨진 `aux` 선은 이때만 보임. 빈 곳 클릭으로 해제.
- **호버 강조**: 선택이 없을 때만. 마우스를 120ms 올린 노드·연결과 이어진 것만 두고 나머지는 45%로 흐림. 선택이 있으면 호버는 무시.
- **움직임 줄이기**: `prefers-reduced-motion` 이거나 사용자가 끄면 모양만 남고 움직임은 멈춤. 끄기 토글 제공.
- 노드가 많을 때(§5.3)는 선택된 경로만 움직이게 해 성능을 지킨다.
- **확장 가능 구조**: 선 종류는 "의미, 모양, 움직임, 색 토큰" 한 묶음으로 데이터 파일에 정의한다. 새 종류를 추가할 때 렌더러 코드를 고치지 않아도 되게 한다. **[설계자 판단]**

### 5.2.1 배치 방향과 기본 정리 옵션 **[사용자 결정: 스파이크 화면 비교 후]**
- **기본 방향은 위→아래**: 맨 위 사용자·진입점, 가운데 서버, 맨 아래 데이터.
- **좌우로 펼쳐지는 게 자연스러운 곳은 좌우로 펼친다**. 사용자 요청은 "필요한 노드는 좌우로 펼쳐져도 좋음"이고, 아래 적용 대상은 설계자 판단이다.
  - 같은 층의 동료 노드(이중화 묶음 안의 WEB#1/#2, MSA 서비스들, DB Active/Standby)는 가로로 나란히 둔다.
  - 외부 서비스 상자는 본 흐름 옆(오른쪽 띠)에 두어 세로 흐름을 끊지 않는다.
  - 구현: ELK 에서 그룹별로 배치 방향을 따로 준다(예: `redundancy_group`·`k8s_cluster` 안은 RIGHT).
- **아래 정리 옵션을 모두 기본으로 켠다.** 사용자가 끌 수 있다.
  1. **보조 연결 숨김**: 모니터링 수집, Bastion·관리자 접속 선. 노드를 선택하면 그 노드의 보조 선만 보인다.
  2. **이벤트 버스 단순화**: Kafka·큐의 발행·구독 선을 "서비스 ↔ 버스" 한 줄로 합친다. 설명 패널에는 발행·구독 토픽을 따로 표시한다.
  3. **연결 라벨은 마우스를 올릴 때만**: 프로토콜·포트 표시. 선택된 노드의 연결 라벨은 항상 보인다.
  4. **같은 두 노드 사이의 중복 선 병합**.
- 연결선은 공통 상위 영역 기준으로 배치·라우팅한다. 스파이크에서 이걸 안 하면 선이 빈 곳에서 꺾이고 겹치는 문제를 확인했다.

### 5.2.2 디자인 방향과 토큰 **[사용자 결정: P1+ "미드나잇 다이얼"]**
시안 비교를 거쳐 정했다(목업: `.superpowers/brainstorm/*/content/design-p1-compare.html`). 형광 네온, 보라 글로우, 노드 왼쪽 색 띠는 "AI 가 만든 디자인" 처럼 보여 사용자가 기각했다.

**원칙**
- 고급 시계의 짙은 청회색 문자판 같은 톤. 거의 무채색으로 두고 **강조색은 샴페인 골드 하나**만 쓴다.
- 강조색이 들어가는 곳은 데이터 흐름 점, 선택 테두리, "방금 수정됨" 표시뿐이다.
- 예외: InfraSketch 로고 마크는 브랜드 표시라 `--accent` 를 쓸 수 있다(2026-10-30 사용자 결정).
- 분류는 색 띠가 아니라 **노드 안 선 아이콘 + 옅은 색조 원**으로 구분한다. 아이콘은 사람, 네트워크, 서버, 저장소, 외부 연결 다섯 가지다.
- 연결선은 가는 점선과 열린 화살촉. 빛 번짐(glow)과 그라데이션은 쓰지 않는다.

- 설명 패널, 대화창 같은 UI 크롬도 같은 토큰을 쓴다. 세부는 구현 중에 다듬는다.
- `prefers-reduced-motion` 이면 흐름 애니메이션을 멈춘다.

### 5.3 가독성 규칙 (반목표 2 대응, 품질 기준) **[설계자 판단]**
- 연결선이 노드를 가로지르지 않는다(직교 라우팅 권장).
- 노드 안 글자는 잘리지 않으며, 기본 확대 배율에서 읽을 수 있는 크기 이하로 줄이지 않는다.
- 라벨끼리, 라벨과 노드가 겹치지 않는다.
- **겹침 방지 규칙** (디자인 시안에서 영역 이름과 이중화 테두리가 노드 글자와 겹친 문제에서 나옴) **[설계자 판단]**:
  - 영역 이름은 영역 상자 위쪽의 **전용 머리 공간**에 둔다. ELK 그룹 padding-top 을 이름 높이 이상으로 잡아, 안쪽 노드가 그 공간을 침범하지 못하게 한다.
  - 선택 테두리는 노드 **바깥쪽**에 그리고, 노드 사이 간격은 선택 테두리 두께 이상으로 둔다.
  - 배지(빠진 정보, 경고)는 노드 모서리 **바깥으로 반쯤 걸치게** 두고, 노드 안 글자 영역은 배지 자리만큼 오른쪽 여백을 비운다.
  - 노드 너비는 글자 길이로 계산하고, 넘치면 말줄임표로 줄인다. 전체 이름은 마우스를 올리면 보인다.
  - "방금 수정됨" 같은 보조 표시는 노드 안에 두거나, 배치 계산에 포함된 자리에만 둔다.
  - 그리는 순서: 영역 → 연결선 → 노드 → 배지·선택 표시.
- **자동 검사**: 대표 구성도(§7.1)를 그려 노드·라벨·배지 사이 겹침을 계산하는 테스트를 둔다. 겹침이 있으면 실패로 처리한다.
- **규모: 구성도 한 장에 노드 30~100개가 흔함 [사용자 결정]** → 아래가 필수:
  - **영역 접기/펼치기**: 접힌 영역은 하나의 노드처럼 보이고 내부 노드 수를 표시. 접힌 영역으로 들어가는 연결선은 묶어서 한 줄로 표시.
  - 노드가 많을 때(대략 40개 초과, 구현자 조정) 처음 열면 하위 영역을 접은 개요 상태로 시작.
  - 이중화 쌍(WEB#1/#2 등)은 묶음으로 접어 "WEB ×2" 로 보일 수 있다.
  - 확대 배율이 낮을 때는 노드 부제·연결 라벨을 숨기고 이름만 표시(단계별 상세).
  - 데이터 흐름 애니메이션은 노드가 많을 때 선택된 경로만 재생하는 등 성능을 지킨다.
- 이 규칙들은 구현 후 대표 구성(§7.1 패턴들)과 노드 100개 규모 샘플로 확인한다.

## 6. 설명 패널 (ℹ️ 설명 탭)

### 6.1 일반 노드 **[사용자 결정]**
순서대로:
1. **이름 + 분류** (예: `⚡ Redis` · 캐시 / 인메모리 저장소)
2. **정의 (한 문장)**: 정식 명칭·약어 풀이와 분류를 포함한 사전식 정의. 비유 쓰지 않음.
   예: "Redis(Remote Dictionary Server)는 데이터를 디스크가 아닌 메모리에 저장해 빠른 읽기와 쓰기 속도를 제공하는 인메모리 NoSQL 키-값(Key-Value) 데이터 구조 스토어입니다."
3. **이 구성에서의 역할**: 일반론이 아닌 이 프로젝트에서의 역할, 1~2 문장.
4. **ADR 요약**: 결정 / 이유 / 대안 / 대가 각 한 줄.
5. **스펙 / SW**: 버전, CPU·RAM·디스크, OS, 대수 등.
6. **서버 정보** (해당 시): hostname, IP, VIP.
7. **연관관계**: 누가 누구를 어떤 방식(프로토콜·포트)으로 부르는지.
8. **연결된 노드**: 칩 목록, 클릭 시 캔버스에서 그 노드로 이동·선택.

### 6.2 용어·약어 노드 (예: L4 로드밸런서) **[사용자 결정]**
- **용어 정의** (예: "L4란? 네트워크 7계층 중 4번째(전송 계층). IP·포트만 보고 트래픽을 나눔")
- **필요한 이유** (간단히)
- **비교** (예: L4 vs L7)

### 6.3 연결선 선택 시 **[설계자 판단]**
- 무엇이 오가나 / 방식(프로토콜·포트·동기/비동기) / 왜 연결됐나 / 방화벽 규칙.

### 6.4 본문 속 용어 풀이 **[설계자 판단, 사용자 유지 동의]**
- 설명 본문의 전문 용어(세션, Cache-aside 등)는 점선 밑줄 표시, 마우스 올리면 한 줄 풀이.

### 6.5 길이 규칙 (반목표 1 대응) **[사용자 결정: 짧게 / 상한 수치는 설계자 판단]**
- 정의 1문장, 역할 1~2문장, ADR 각 항목 1줄, 용어 풀이 1문장.
- 항목별 글자 수 상한을 두고(대략 정의 120자, 역할 150자, ADR 항목 80자 내외 — 구현자가 조정 가능), 초과 시 AI 에 짧게 다시 쓰도록 재요청. 글자 수 안에 들어도 Clef-Flash 품질 점수(§4.6)가 기준을 넘으면 재요청. 재작성은 최대 2회. **[설계자 판단: 횟수]**
- 설명은 AI 가 생성하며, 사용자는 대화로 수정 요청할 수 있다.

### 6.6 설명 생성 시점 **[설계자 판단]**
- 구성도 스트림에는 구조 명령(노드·연결·영역·속성)만 넣어 "하나씩 나타남" 속도를 지킨다. 설명은 스트림에 넣지 않는다.
- 구조 스트림이 끝나면 노드별 설명을 백그라운드에서 생성해 캐시한다. 생성 전에 노드를 누르면 그 노드를 우선 생성한다(로딩 표시). 용어 사전에 있는 정의는 즉시 표시한다.
- 노드의 종류·SW·연결이 바뀌면 그 노드(와 연결 상대)의 설명 캐시를 무효화하고 다시 생성한다.
- 글자 수 초과 재작성은 이 설명 생성 단계에서만 일어난다.

### 6.7 설명의 출처와 용어 사전 **[사용자 결정: DB 용어 사전, 자동 추가 + 미검수]**
- 용어 사전은 **DB 테이블**로 관리한다. 항목: 용어, 정식 명칭/약어 풀이, 분류, 한 문장 정의, 필요한 이유, 비교 대상, 검수 상태, 출처(초기/AI).
- 초기 데이터: 구현자가 자주 쓰는 SW·용어 50개 안팎의 한국어 초안을 시드로 넣는다(Redis, Nginx, L4/L7, VIP, NAT, DMZ, CDN, Kafka 등). 시드도 처음엔 "미검수" 상태로 두고 사용자가 검수한다. **[설계자 판단]**
- 노드 정의는 사전에 있으면 사전에서 즉시, 없으면 AI 가 생성하고 **그 결과를 사전에 자동 추가하며 "미검수" 배지**를 붙인다.
- **용어 사전 화면**: 목록·검색·수정·검수 완료 처리. 설명 패널의 미검수 정의 옆에 배지 표시.
- "이 구성에서의 역할 / ADR" 은 프로젝트 맥락이므로 사전이 아니라 노드별로 AI 가 생성.
- 구성 패턴·경고 규칙은 리포지토리 데이터 파일로 관리(§10). **[설계자 판단]**

### 6.7.1 3C-1 결정 **[사용자 결정, 2026-10-30]**
- 노드 설명은 화면이 차례로 요청해 만든다(대화가 끝나거나 구성도를 열면 설명이 없거나 낡은 노드를 하나씩, 누른 노드 우선). 결과는 DB 캐시에 저장한다.
- 연결선 설명(§6.3)은 연결선을 눌렀을 때만 만든다.
- 용어 사전은 사용자별이다. 시드는 사용자마다 복사한다.
- 설명 수정(§6.5 "대화로 수정 요청")은 설명 패널의 "다시 쓰기" + 요청 한 줄로 한다. 본 대화로는 하지 않는다.
- 3C 는 3C-1(설명·용어 사전)과 3C-2(§6.8)로 나눈다.

### 6.8 노드에 대해 물어보기 **[사용자 결정, 2026-10-29 — 3C 에서 구현]**
- 노드별 질문 입력 UI 가 뜨고, 엔터나 전송을 누르면 그 질문으로 시작하는 **새 대화 세션**이 대화 탭 영역에 추가된다.
- AI 는 그 노드의 세부 메타정보(종류·SW·속성·연결·설명)를 근거로 답한다. 구성은 바꾸지 않는다.
- 세부(세션 목록 모양, 세션 전환, 저장 방식)는 3C 계획에서 정한다.

## 7. 지식: 구성 패턴과 경고

### 7.1 구성 패턴 라이브러리 **[사용자 결정: WEB-WAS-DB 외 다양한 패턴 / 목록은 설계자 판단]**
최소 포함 후보:
- WEB-WAS-DB 이중화 (VIP, DB Active/Standby, DB 중계/복제)
- L4/L7 로드밸런싱 + 오토스케일링
- 캐시 계층 (Redis, Cache-aside)
- 메시지 큐 기반 비동기 처리 (Kafka/RabbitMQ)
- Kubernetes 클러스터 (Ingress, Service, Pod)
- CDN + 정적 호스팅
- 서버리스 (API Gateway + 함수)
- DR(재해복구) 구성 (멀티 AZ/리전)
- 외부 연동 (PG, OAuth 소셜 로그인)

용도: AI 프롬프트의 기준 지식, 초안 생성의 출발점, 경고 판단 기준.

### 7.2 이상한 구성 경고 **[사용자 결정]**
- 구성이 표준 패턴에서 위험하게 벗어나면 대화와 설명 패널에서 경고 + 가이드 제공.
- 예: DB 가 공개 구역에 있음, 단일 장애점(1대뿐인 핵심 서버), 외부→내부 직접 접근에 방화벽 없음, 캐시만 있고 원본 DB 없음.
- 확실한 규칙은 코드 규칙 검사로, 애매한 판단은 Clef-Flash `noul` 판정으로(§4.6). **[사용자 결정: Clef 사용 / 분담은 설계자 판단]**
- 경고는 강요가 아니라 제안: 사용자가 "의도된 구성" 으로 무시 처리 가능.
- 결정 **[사용자 결정, 2026-10-30]**:
  - 경고는 AI 대화 차례가 구성을 바꾼 뒤 서버에서 계산한다(코드 규칙 → Clef 판정 → 새 경고만 Qwen 문구). 결과는 버전 상태에 함께 저장한다.
  - "의도된 구성" 무시는 구성도 상태에 저장한다(버전과 함께 되돌려진다).
  - 경고는 대화 끝 "주의: …" 줄과 설명 패널 "주의할 점" 절에 보인다. 전체 목록 화면은 없다.
  - 노드에는 빠진 정보 숫자 배지와 경고 "!" 배지를 나란히 둔다.
  - 구성 패턴(§7.1)은 생성 프롬프트의 기준 지식과 경고 규칙의 근거로만 쓴다(패턴 선택 화면 없음).
  - 구간 "방화벽 필요 여부"(§8.1)는 외부→내부 직접 접근 규칙으로 판단한다.

## 8. 빠진 정보 채우기 **[사용자 결정: B안 + 대화 연동]**

### 8.1 대상 항목
서버형 노드 기준: hostname, CPU, RAM, 디스크, OS, IP, VIP(이중화 묶음), SW/버전. 구간 기준: 포트(동기·비동기 연결의 프로토콜/포트 라벨). DB 기준: 복제 방식(동기/비동기). 노드 종류별 필요 항목은 노드 타입 정의(catalog 의 필수 항목)에서 정한다(구현자 재량으로 확장).
- 구간의 "방화벽 필요 여부"는 입력 항목이 아니라 위험 판단이므로 경고(§7.2, 3B)로 넘긴다. **[사용자 결정, 2026-10-29]**

### 8.2 동작
- 구성도가 그려지거나 바뀌면 빈 항목을 계산.
- **노드 배지**: 노드 오른쪽 위에 빈 항목 수(빨간 숫자).
- **체크리스트 알림**: 대화 탭 상단에 "채워야 할 정보 (N)". 펼치면 노드/구간별로 빈 항목 + 입력 폼. "모름" 표시 가능(카운트에서 빠지되 표시는 남음).
- "모름" 은 노드·연결의 `unknown` 목록(항목 키)으로 구성도 상태에 저장한다 — 버전과 함께 되돌려진다. **[사용자 결정, 2026-10-29]**
- 폼은 노드(또는 연결)마다 "저장" 버튼이 있고, 한 번 저장하면 버전 하나("직접 입력")가 생긴다. **[사용자 결정, 2026-10-29]**
- 노드 배지 클릭 → 해당 항목으로 이동.
- **대화에서도 알림**: AI 응답 끝에 "빠진 정보 N개가 있어요" 한 줄.
- 대화로 값을 알려 주면(예: "WAS 두 대 다 4코어 16기가야") AI 가 해당 칸에 반영한다. Clef 의도 분류에 직전 AI 메시지와 열린 체크리스트 항목을 함께 보내 이 답을 정확히 알아본다.
- ~~"대화로 물어보기" 가이드 대화~~ — 빠진 정보를 AI 가 하나씩 묻는 가이드 대화는 하지 않는다(폼·본 대화로 충분). **[사용자 결정, 2026-10-29]** 대신 노드에 대해 묻는 대화는 §6.8 로 옮긴다.
- 폼에 직접 입력한 값도 구조 변경과 동일하게 변경 이력에 남는다. (폼 입력은 "구조"가 아닌 "속성 값 입력"이므로 §4.1 의 대화 전용 원칙의 예외로 허용 — 사용자가 B안을 고름) **[설계자 판단]**

## 9. 프로젝트 관리 **[사용자 결정]**

- **프로젝트** ⊃ **구성도 여러 장** (예: 운영/개발/DR, 현재/개선안)
- 구성도마다 **대화 기록** 보관. **[설계자 판단: 대화는 구성도 단위]**
- **변경 이력**: AI 변경 1회(응답 1번) 또는 폼 입력 저장 1회마다 버전 1개 자동 생성. 버전 목록 보기, 이전 버전 보기, 되돌리기, 두 버전 비교(추가/삭제/변경 노드 색 표시). **[설계자 판단: 이력 단위·비교 기능]**
- **되돌리기는 비파괴적**: 이전 버전으로 되돌리면 그 내용으로 새 버전이 생긴다(기존 이력은 삭제하지 않음). 대화는 이어지며, 대화창에 "v3 로 되돌림" 시스템 메시지를 남기고 AI 맥락에도 현재 상태를 다시 전달한다. 각 버전은 그 버전을 만든 대화 메시지와 연결된다. **[설계자 판단]**
- **응답 중단 처리**: AI 응답이 오류·사용자 중단으로 끊기면 그때까지 적용된 변경을 "중단됨" 표시가 붙은 버전으로 남긴다(사용자가 그 자리에서 되돌릴 수 있음). **[설계자 판단]**
- 프로젝트·구성도 생성/이름 변경/삭제/복제.

### 10.1 실행 환경 **[사용자 결정]**

- 서비스명: **InfraSketch** (`infra-sketch`) — **[사용자 결정]**. Clef 키 발급 단위로도 쓴다.
- 모든 키·주소는 `.env` 환경변수로 받는다. 키는 사용자가 `.env` 에 직접 넣는다 **[사용자 결정]**. 저장소에는 `.env.example`(값 없음)만 커밋한다.

  ```env
  QWEN_CODER_KEY=
  QWEN_MODEL=qwen3.8-flash-next
  QWEN_API_URL=https://open-llm.cudo.co.kr:8877/v1   # 사용자 .env 기준(2026-10-29 동작 확인). 내부망 http://192.168.102.105:8000/v1 도 동작

  CLEF_API_URL=http://192.168.102.105:30000
  DATABASE_URL=
  AUTH_SECRET=
  SMTP_HOST= / SMTP_PORT= / SMTP_USER= / SMTP_PASS= / SMTP_FROM=
  ```
- 사내 서버 배포이므로 내부망 URL 을 기본값으로 둔다. 망 밖에서 돌릴 때는 외부 URL(Qwen `https://open-llm.cudo.co.kr:8877/vllm/v1`, Clef `https://open-llm.cudo.co.kr:7777`)로 교체.

### 10.2 로그인·회원 **[사용자 결정]**

- 나중에 사내 Nexus 로그인으로 연동 예정 → 인증은 Auth.js provider 교체/추가로 끝나도록, 사용자 테이블에 외부 계정 연결(accounts) 구조를 둔다.

### 10.3 Qwen 호출 규칙 **[사용자 제공 가이드]**
- `openai` npm SDK, `baseURL = QWEN_API_URL`, `POST /chat/completions`, `Authorization: Bearer QWEN_CODER_KEY`.
- 스트리밍(`stream: true`), `temperature`, `max_tokens` 등 일반 OpenAI 파라미터 사용 가능.
- **thinking 끄기**: 요청 본문 최상위에 `chat_template_kwargs: { enable_thinking: false }` (Node SDK 에선 `extra_body` 가 아니라 이 필드를 직접 넣는다). 실시간으로 노드가 바로 나타나야 하므로 기본 off. **[설계자 판단]**
- 방어 처리(가이드의 기존 서비스 패턴):
  1. 429·503·5xx → 2초 → 4초 → 8초, 최대 3회 재시도.
  2. 응답에서 `<think>…</think>` 블록 제거(스트리밍 중에도 걸러서 화면/파서에 넘기지 않음).
  3. JSON 응답을 감싼 ```` ```json ```` 코드 펜스 제거 후 파싱.
  4. 빈 응답이면 1회 재호출.
  5. 긴 입력은 잘라서 보냄 — 이 서비스에서는 구성도 상태를 요약 형태로 보낸다.
- tool calling 지원 여부·컨텍스트 길이(`max_model_len`)는 가이드에 없음 → 시작 시 `/models` 와 시험 호출로 확인하고, tool calling 미지원이면 JSON Lines 폴백(§4.5). 컨텍스트가 작으면 구성도 요약을 영역 단위로 줄인다. **[설계자 판단]**
- 명령 스키마 검증 + 재요청은 필수.

### 10.4 Clef-Flash 호출 규칙 **[사용자 제공 가이드: open-llm.cudo.co.kr:7777]**
- `POST {CLEF_API_URL}/v1/systemone`, `Authorization: Bearer CLEF_API_KEY`(`clef_` 로 시작). OpenAI 형식 아님.
- 본문: `model: "Cloudflare/clef-flash"`, `state`, `questions`(`noul` / `choice` / `score`). 질문 안의 정의되지 않은 키는 422.
- 입력 한도 16,384 토큰(초과 시 `state` 뒤쪽이 잘림), 본문 20MB, 타임아웃 30초 이상.
- **브라우저에서 직접 호출 금지(CORS 차단)** — 반드시 Next.js 서버 쪽에서 호출.
- 재시도: 429(`Retry-After: 1`)는 1초부터, 502/503/504 는 5초 → 15초 → 45초, 최대 3회. 실패 시 §4.6 대체 동작.
- 키별 동시 요청 상한(2·4·8) 이하로 서버에서 동시 호출 수를 제한한다.
- 키 발급 요청 내용 **[사용자 결정: 서비스명 / 나머지 설계자 제안]**: 서비스명 InfraSketch, 환경 `dev`, 담당자 사용자 본인, 용도 "인프라 구성도 대화 도구의 요청 의도 분류·이상 구성 판정·설명 품질 검사", 동시 상한 2.

## 12. 스파이크 결과 (2026-10-29) 와 반영 사항

버리는 시험 코드로 Qwen `qwen3.8-flash-next`(thinking off, temperature 0.3, JSON Lines 스트리밍)와 Clef-Flash 를 실제 호출해 확인했다.

### 12.1 Qwen 구성도 생성
| 시나리오 | 첫 명령 | 전체 | 노드/그룹/연결 | 형식 오류 |
|---|---|---|---|---|
| 결제·카카오 로그인 쇼핑몰 | 1.1초 | 9.0초 | 12/8/15 | 0 |
| IDC WEB-WAS-DB 이중화 + DB 중계 | 1.1초 | 7.3초 | 9/6/12 | 0 |
| EKS MSA + Kafka | 1.1초 | 9.8초 | 13/7/18 | 0 |
| 대규모 멀티 AZ 커머스 | 1.1초 | 18.6초 | 33/18/33 | 0 |
| 수정 요청(WAS#1 RAM, L4 삽입, Redis 추가) | 1.4초 | 3.7초 | 기존 id 정확히 수정, 기존 WEB→WAS 연결 제거 후 L4 경유로 교체 | 0 |

- **실시간 생성은 성립**: 첫 노드까지 약 1초, 이후 명령이 꾸준히 도착.
- **전달 방식: JSON Lines 를 기본으로 확정** **[설계자 판단, 스파이크 근거]**. tool calling 도 동작하지만 `kind` 를 허용값 밖(`webserver`, `database`)으로 지어냈다. JSON Lines + 프롬프트 허용값 목록 + 검증은 오류 0건. tool calling 은 enum 스키마를 넣은 대안 경로로만 유지.
- **프롬프트 규칙이 결과를 크게 바꿈** — 1차엔 라벨이 영어, AWS 관리형(MSK·모니터링)을 "외부 서비스"로 묶음. 아래 규칙 추가 후 해결: 표시 문구는 한국어(제품명은 원어), `external_service` 는 타사 서비스에만, Kafka=`stream`/SQS=`queue`, CDN·WAF 는 VPC 밖, 사용자 진입 연결 필수, 위험 시 `warn`. 이 규칙들은 패턴 라이브러리와 함께 시스템 프롬프트의 고정 부분이 된다.
- **가정 목록(§4.5.1) 동작 확인**: 애매한 요청에서 환경·규모·이중화·배포 방식 가정을 스스로 냄.
- **약점 1 — AZ 같은 가로지르는 경계**: 대규모 시나리오에서 AZ 그룹을 만들고 아무것도 넣지 않음(서브넷이 AZ 아래가 아니라 VPC 아래에 생김). → **AZ 는 중첩 그룹이 아니라 노드/서브넷의 속성(`az`)으로 두고, 캔버스에서 AZ 별 띠(lane)나 배지로 표현**한다. **[설계자 판단]**
- **약점 2 — 이중화 묶음 이름**: 4~6대 서버도 `redundancy_pair` 로 묶음. → 그룹 종류 이름을 `redundancy_group` 으로 바꾼다(2대 이상, VIP 라벨). **[설계자 판단]**
- **약점 3 — Qwen 의 경고 품질이 들쭉날쭉**: 막연한 경고를 내거나 수정 후엔 안 냄. → 경고 판단은 코드 규칙 + Clef(§4.6)가 맡고, Qwen 은 판정된 위험의 문구만 쓴다(설계 그대로 유지, 근거 확보).

### 12.2 Clef-Flash 판정
- 응답 시간 70~90ms. 앞단 분기용으로 충분히 빠름.
- **의도 분류 8건 중 7건 정답**. 실패: IP 목록만 입력("10.0.2.11, 10.0.2.12")을 구조 변경으로 분류. → `state` 에 **직전 AI 질문 / 열린 체크리스트 항목**을 함께 넣는다. 확신도 0.6 미만은 Qwen 일반 경로. **[설계자 판단]**
- **이상 구성 판정**: 위험 구성은 DB 외부 노출 0.97·단일 장애점 0.96, 안전 구성은 0.01·0.14 로 뚜렷이 갈림.
- **설명 품질 점수**(0 쉽고 간결 ~ 2 어렵고 장황): 사전식 한 문장 0.96, 전문용어 나열 장문 1.89. 재작성 기준값은 1.3 내외에서 시작해 조정. **[설계자 판단]**

### 12.3 연결 정보에서 발견한 것
- 처음 `.env` 의 `QWEN_API_URL`(스킴 없음, `/chat/completions` 까지 포함)이 SDK baseURL 형식과 달랐음 → 앱은 시작 시 URL 형식을 정규화(끝의 `/chat/completions` 제거, 스킴 확인)하고 `/models` 로 연결을 점검해 오류를 화면에 보여준다. **[설계자 판단]**
