# 배치 가독성 3·4단계 — 처음 접기, 묶음 접기 단추, 엇갈림 줄이기

날짜: 2026-11-17 · 상태: 승인됨(2026-11-17), 구현 중 3번 설정 범위를 좁힘

## 왜 하는가

배치 조화 프로젝트(`2026-11-04-layout-harmony-stage1-design.md`)의 남은 두 단계다. 3단계는 "배치 모양", 4단계는 "규모 대응"이었다. 사용자가 지금 불편하다고 고른 것은 두 가지다.

- **큰 구성도가 다 접혀 열린다.** 노드가 40개를 넘으면 맨 바깥 영역만 남기고 안쪽 영역을 전부 접는다(`display.ts` `initialCollapsed`). 노드 50개짜리 구성도가 상자 9개로 열려서, 안에 무엇이 있는지 하나씩 펼쳐 봐야 한다.
- **선이 많이 엇갈린다.** 다 펼쳐 여는 중간 크기 구성도(노드 33개 샘플)에 교차가 26개 있고, 큰 구성도를 펼치면 수십~수백 개다.

1단계에서 3단계 몫으로 넘긴 "16px 미만으로 나란한 선"은 연결선 가독성 작업(`2026-11-16-edge-routing-readability-design.md`)에서 모든 기준 구성도 0이 됐다. 그래서 이번에는 다루지 않는다.

## 재 본 것

기준 구성도(`tests/fixtures/layout/`)와 샘플(`tests/fixtures/spike.ts`)에 후보 방식을 실제로 돌려 쟀다. 숫자는 `measureLayout` 값이다.

### 처음 접기

"보이는 상자"는 보이는 노드 수와 접힌 영역 상자 수를 더한 값이다.

| 구성도 | 지금 규칙 | 깊은 영역부터 접어 40개 이하 | 모두 펼침 |
|---|---|---|---|
| state-50 | 상자 9, 교차 0, 2.2:1 | 상자 40, 교차 39, 3.4:1 | 상자 50, 교차 69, 4.1:1 |
| state-100 | 상자 11, 교차 1, 2.5:1 | 상자 32, 교차 1, 4.9:1 | 상자 100, 교차 124, 7.9:1 |
| state-200 | 상자 11, 교차 1, 2.5:1 | 상자 21, 교차 1, 3.8:1 | 상자 200, 교차 611, 12.1:1 |

s4(노드 33개, 40개 이하라 다 펼쳐 연다)에서 이중화 묶음 5개만 접으면 교차 26 → 5, 상자 33 → 20, 크기 2168×1364 → 1230×1158 이 된다.

- 배치 시간은 t50 에서 약 1.5배다(state-50 접은 화면 0.10초 → 0.13초, state-100 모두 펼침 0.36초 → 0.60초, Node 에서 잰 값).

### 왼쪽→오른쪽 배치 (이번에 하지 않음)

뒤처리를 고치지 않고 `elk.direction` 만 RIGHT 로 바꿔 잰 어림값이다.

| 구성도·화면 | 위→아래 (지금) | 왼쪽→오른쪽 |
|---|---|---|
| state-50, 40개 이하로 접음 | 교차 39, 3.4:1 | 교차 23, 1.3:1 |
| state-100, 40개 이하로 접음 | 교차 1, 4.9:1 | 교차 6, 1.0:1 |
| state-100, 모두 펼침 | 교차 124, 7.9:1 | 교차 71, 0.4:1 |
| state-portal | 교차 0, 1.1:1 | 교차 2, 5.3:1 |
| s1 | 교차 1, 0.8:1 | 교차 0, 5.2:1 |

큰 구성도에는 좋고 작은 구성도에는 나쁘다. 외부 서비스 열, 평소 화면 이름 자리, 선 띄우기(`separate.ts`)가 모두 위→아래를 전제로 짜여 있어 고칠 곳이 많다. 사용자가 이번에는 빼고 따로 검토하기로 했다.

## 목표

1. 노드가 40개를 넘는 구성도를 처음 열면, 망·서브넷 같은 바깥 구조와 그 안의 노드가 보이고 가장 안쪽 영역만 접혀 있다. 보이는 상자는 40개 이하다.
2. 어느 크기의 구성도에서든 이중화 묶음을 한 번에 접거나 펼 수 있다.
3. 교차가 지금보다 줄어든다: s4 26 → 21, state-50 접은 화면 39 → 26, 모두 펼친 큰 구성도 15~20% 감소.
4. 노드 40개 이하 구성도의 처음 화면은 지금과 같다(다 펼침).

## 하지 않는 것

- 배치 방향 바꾸기(왼쪽→오른쪽), 화면 비율에 맞춘 줄바꿈. 위 측정과 함께 남은 과제로 적어 둔다.
- 아주 멀리 볼 때의 영역 이름·확대 단계별 표시. 사용자가 불편한 점으로 고르지 않았다.
- 접힘 상태를 구성도마다 저장해 다음에 열 때 되살리기. 지금처럼 열 때마다 처음 접기 규칙으로 시작한다.
- 노드 40개 이하 구성도를 교차 수를 보고 자동으로 접어 여는 것. 사용자가 "다 펼치고 단추를 둔다"를 골랐다.
- 대화·MCP 쪽 변경.

## 설계

### 1. 처음 접기: 깊은 영역부터, 보이는 상자 40개 이하

`display.ts` 의 `initialCollapsed(state)` 를 바꾼다. 부르는 곳(`defaultDisplayOptions`, `DiagramWorkspace` 의 `optionsFor`)과 부르는 시점은 그대로다. 대화로 구성이 바뀐 뒤에는 지금처럼 사용자의 접힘 상태를 유지한다.

규칙:

1. 노드가 40개 이하면 아무것도 접지 않는다(지금과 같다).
2. 넘으면 접을 후보를 순서대로 하나씩 접고, 접을 때마다 보이는 상자 수를 센다. 40개 이하가 되면 멈춘다.
3. 후보는 부모가 있는 영역(맨 바깥 영역은 접지 않는다, 지금과 같다) 가운데 안에 든 노드가 2개 이상인 것이다. 노드가 하나뿐인 영역은 접어도 상자 수가 줄지 않는다.
4. 순서는 깊이가 깊은 영역 먼저, 같은 깊이면 안에 든 노드가 많은 영역 먼저, 그래도 같으면 `state.groups` 에 든 순서다. 같은 구성도는 언제나 같은 결과가 나온다.
5. 후보를 다 접어도 40개를 넘으면 그대로 둔다(영역 없이 노드만 많은 구성도. 지금 규칙과 같은 결과다).

"보이는 상자 수"는 접힌 조상이 없는 노드 수와, 접혔고 접힌 조상이 없는 영역 수의 합이다. 문턱값과 예산은 같은 40 이고 상수 하나(`NODE_THRESHOLD`)를 쓴다.

기준 구성도에서의 결과는 위 표와 같다(state-50 은 이중화 묶음 10개가 접히고 서브넷은 열린다, state-100 은 상자 32개, state-200 은 상자 21개).

### 2. 이중화 묶음 접기 단추

캔버스 도구 모음의 「보기」 묶음(`Canvas.tsx`, 「보기」 메뉴 옆)에 단추 하나를 둔다.

- 대상은 `groupKind === "redundancy_group"` 인 영역 전부다. 쿠버네티스 클러스터 같은 다른 영역은 건드리지 않는다.
- 펼쳐진 이중화 묶음이 하나라도 있으면 글자는 「묶음 접기」이고, 누르면 이중화 묶음을 모두 접는다. 모두 접혀 있으면 「묶음 펼치기」이고, 누르면 모두 편다. `aria-pressed` 는 쓰지 않고 글자가 다음 동작을 말한다.
- 구성도에 이중화 묶음이 없으면 단추를 그리지 않는다.
- 접힌 조상 안에 있어 보이지 않는 이중화 묶음도 함께 바뀐다(조상을 펼쳤을 때 같은 상태로 보인다).
- 누른 뒤의 처리는 영역 접기 단추 하나를 눌렀을 때(`toggleGroup`)와 같다: 배치를 다시 하고, 펼친 줄기와 선택을 푼다. 카메라 동작도 그때와 같게 한다.
- 이력 보기·비교 화면에서도 쓸 수 있다(보기만 바꾸고 구성도를 바꾸지 않는다). 영역 접기 단추가 그 화면에서 막혀 있다면 똑같이 막는다.
- 도구 모음이 좁아 아이콘만 남을 때(`data-compact`)는 아이콘과 `title` 로 보인다. 아이콘은 기존 도구 아이콘과 같은 선 굵기·크기로 새로 그린다.

### 3. 배치 엔진 탐색 강화

`layout.ts` 에 두 설정을 더한다.

- `"elk.layered.crossingMinimization.hierarchicalSweepiness": "1"` — 언제나.
- `"elk.layered.thoroughness": "50"` — 보이는 상자(노드 + 접힌 영역)가 60개 이하인 화면에서만(`THOROUGH_MAX_BOXES`).

**구현 중 바뀐 점(2026-11-17, 사용자 선택).** thoroughness 를 모든 화면에 넣으면 state-100·200 을 모두 펼친 화면에서 16px 미만으로 나란한 선이 48px·428px 생겼다(교차는 124 → 104, 611 → 487). "평행 0 을 지킨다"를 어기므로 멈추고 물었고, 사용자가 "보이는 상자 60개 이하일 때만 강화"를 골랐다. 그래서 100개 이상을 모두 펼친 화면은 값이 지금과 같고, 목표 3 의 "모두 펼친 큰 구성도 15~20% 감소"는 state-50(69 → 56)에만 해당한다. 큰 화면의 배치 시간도 늘지 않는다.

다른 설정은 재 봤지만 넣지 않는다: greedySwitch 양방향(변화 없음), sweepiness −1(교차가 크게 늚), 층 나누기 전략 바꾸기(COFFMAN_GRAHAM·MIN_WIDTH·LONGEST_PATH: 구성도마다 좋고 나쁨이 갈림), 노드 놓기 BRANDES_KOEPF(state-25 교차 2 → 10), considerModelOrder(뒤처리가 깨짐).

### 받아들이는 변화 (승인 필요)

회귀 시험(`layoutRegression.test.ts`)은 교차·꺾임이 기준선보다 늘면 실패한다. 이번 변경으로 기준선(`tests/fixtures/layout/baseline.json`)을 다시 재야 하고, 그 가운데 **나빠지는 값**은 아래 둘이다. 사용자가 받아들여야 넣는다.

| 구성도 | 값 | 지금 | 바뀐 뒤 | 까닭 |
|---|---|---|---|---|
| s3 (노드 13개 샘플) | 꺾임 | 34 | 36 | thoroughness 를 올리면 생긴다. 교차는 3 그대로다. |
| s4 (노드 33개 샘플) | 꺾임 | 80 | 82 | sweepiness 로 교차가 26 → 21 로 줄면서 생긴다. |

받아들이지 않을 때의 대안: thoroughness 를 빼면 s3 는 그대로지만 큰 구성도의 교차 감소(39 → 26 등)가 사라지고, s4 만 21/86 이 된다(꺾임 +6).

그 밖에 기준선이 바뀌는 곳:

- state-50·100·200 의 기본 화면: 처음 접기가 바뀌어 상자 수·교차·꺾임·크기가 모두 달라진다(위 표). 교차가 0~1 에서 state-50 은 26 으로 는다. 처음 화면에 더 많이 보여 주는 대가이고 사용자가 고른 방향이다.
- 모두 펼친 화면: 교차가 줄어든 새 값으로 낮춘다.
- 16px 미만 평행 0, 노드 통과 0, 이름 겹침 0, 빠진 이름 0 은 **그대로 지킨다**. 다시 재서 어기는 구성도가 있으면 멈추고 사용자에게 알린다.

## 시험

- `display.test.ts`: 처음 접기 규칙. 40개 이하면 빈 집합, 넘으면 깊은 영역부터 접혀 보이는 상자가 40개 이하, 노드 하나짜리 영역은 접지 않음, 후보를 다 접어도 넘는 경우, 같은 입력에 같은 결과. 지금의 "> 40 nodes starts with non-root groups collapsed" 시험은 새 규칙으로 고친다.
- 기준 구성도 state-50·100·200 의 처음 화면 보이는 상자 수(40·32·21)를 시험으로 고정한다.
- `layoutRegression.test.ts`: 기준선을 다시 재고 머리말 주석에 이번 변화를 적는다.
- 단추: 글자가 상태에 따라 바뀌는지, 누르면 이중화 묶음만 모두 접히고 펴지는지, 이중화 묶음이 없으면 보이지 않는지(단위 시험), 실제 화면에서 눌러 상자 수가 바뀌는지(E2E 하나).
- 처음 접기에 기대는 기존 시험(`useDiagramView.test.tsx`, `Canvas.test.tsx` 등 `initialCollapsed`·`defaultDisplayOptions` 를 쓰는 곳)은 돌려 보고 깨지는 것만 새 규칙에 맞춘다.

## 위험

- **배치 시간.** 탐색 강화로 약 1.5배다. 노드 200개를 모두 펼친 화면은 지금 설정으로도 Node 에서 0.9초가 걸리고(강화한 설정으로는 재지 않았다), 브라우저에서는 더 걸릴 수 있다. 구현 뒤 브라우저에서 state-100·200 을 열어 처음 배치와 "묶음 펼치기" 시간을 재고, 눈에 띄게 느리면 thoroughness 를 낮춘 값(25)을 사용자에게 제안한다.
- **state-50 처음 화면이 넓다.** 3.4:1 이라 화면에 맞추면 글자가 작다. 이번 범위에서는 고치지 않는다(배치 방향 과제).
- **기준선을 다시 재는 일.** 다른 값이 뜻밖에 나빠지면 그 자리에서 멈추고 알린다. 조용히 기준선을 올리지 않는다.

## 남은 과제 (이번에 하지 않음)

- 배치 방향 고르기: 큰 구성도는 왼쪽→오른쪽이 화면 비율에 가깝고 교차도 적다(위 측정). 자동으로 고를지 단추로 둘지, 뒤처리를 어떻게 방향에 무관하게 만들지는 별도 설계로 다룬다.
- 아주 멀리 볼 때의 영역 이름과 확대 단계별 표시.
- 접힘 상태를 구성도마다 기억하기.
