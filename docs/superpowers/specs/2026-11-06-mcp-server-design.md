# Claude Code 연동(MCP 서버) — 설계

날짜: 2026-11-06 · 상태: 승인됨 (2026-11-06)
먼저 할 일: `2026-11-06-network-character-and-link-guess-design.md`(망 지식)를 구현한 뒤에 만든다. **(사용자)**

표기: **(사용자)** = 사용자가 정한 것, **(제 판단)** = 설계자가 정한 것.

## 왜 하는가

서비스 코드 저장소에서 Claude Code로 작업하다가 "이 저장소 인프라 구성도 그려 줘"라고 하면, Claude Code가 docker-compose·설정 파일·코드를 읽고 InfraSketch에 구성도를 그린다. 나중에 "Redis 추가했으니 구성도에도 반영해 줘"라고 하면 고친다. 프로젝트를 만드는 일부터 구성도를 그리고, 읽고, 고치는 일까지 Claude Code 안에서 끝난다. **(사용자)**

원래 설계에서 "나중에"로 미뤄 둔 "코드 저장소를 읽어 자동으로 그리기"를 InfraSketch가 직접 만들지 않는다. Claude Code가 그 일을 맡는다.

지금은 사용자 본인이 쓰고, 나중에는 팀원들도 각자의 Claude Code에서 쓴다. **(사용자)**

## 목표

### 1. 누가 그리나

- **Claude Code가 직접 그린다. (사용자)** Claude가 노드·연결·영역·흐름 명령을 보내고, InfraSketch는 검사하고 저장한다. InfraSketch의 Qwen은 MCP 경로에서 쓰지 않는다.
- **Claude는 InfraSketch의 그리기 방식을 익히고 그린다. (사용자)**
  - **규칙은 한 곳에서 쓴다. (제 판단)** 지금 Qwen 시스템 프롬프트(`src/server/chat/prompt.ts`의 `SYSTEM_PROMPT`)에 들어 있는 그리기 규칙과 표준 패턴(`patternPromptBlock`), 종류 목록을 한 모듈로 떼어 낸다. Qwen 프롬프트와 MCP 안내서가 그 모듈을 같이 쓴다. 규칙을 고치면 양쪽이 함께 바뀐다.
  - Qwen에만 해당하는 말(JSONL 형식, `say` 명령, 이어 쓰기, `warn` 금지 등)은 공용 모듈에 넣지 않는다.

### 2. 어디서 띄우나

- **InfraSketch 앱 안에 둔다. (사용자)** 앱에 MCP 주소 `/api/mcp`를 연다. 나중에 앱을 사내 서버에 배포하면 팀원들도 같은 주소를 쓴다.
- **방식. (제 판단)** MCP 공식 TypeScript SDK의 Streamable HTTP 방식을 Next.js 라우트 하나로 받는다. 상태를 기억하지 않는(stateless) 방식이며, 요청마다 키로 계정을 확인한다.
- **접속은 계정마다 발급한 키로 한다.**
  - `Authorization: Bearer <키>` 로 보낸다. `/api/mcp`는 로그인 세션 미들웨어를 거치지 않고(`middleware-paths.ts`의 공개 경로), 라우트가 직접 키를 확인한다.
  - 키 하나로는 그 계정의 프로젝트만 보인다.

### 3. 키 관리 (제 판단)

- 계정 화면(사이드바 계정 메뉴)에 "Claude Code 연결"을 둔다.
  - 키 이름을 적고 "키 만들기"를 누르면 키를 **한 번만** 보여 준다.
  - 그 옆에 Claude Code에 붙여 넣을 설정 예(`claude mcp add --transport http infrasketch <앱 주소>/api/mcp --header "Authorization: Bearer <키>"`)를 함께 보여 준다.
- 키는 해시만 저장한다. 목록에는 이름, 만든 날, 마지막 사용 시각, 앞 몇 글자만 보이고, 지울 수 있다.
- 지운 키는 바로 쓸 수 없다.

### 4. 도구

모든 도구 설명에 "InfraSketch에 처음 그리기 전에 `get_guide`를 먼저 읽으세요."를 넣는다. 결과는 사람이 아니라 Claude가 읽는 글이다. 짧은 머리말과 JSON으로 준다. **(제 판단)**

**배우기**
- `get_guide` — InfraSketch 그리는 법.
  - 명령 형식(아래 `apply_commands`가 받는 것), 노드·영역·연결 종류와 노드별 속성 칸, 그리기 규칙, 표준 구성 패턴을 담는다.
  - 그 계정의 망 지식도 담는다. 망 종류(key·이름·다른 이름·등급)와 기관 연결 규칙, 기본 등급 규칙이다.
  - "구성도가 바뀌었으면 다시 읽고 고친다", "모르는 값은 비워 둔다" 같은 사용법도 담는다.

**찾기·만들기**
- `list_projects` — 프로젝트와 그 안 구성도 목록(id, 이름, 최신 버전 번호).
- `create_project(name)` — 새 프로젝트. 기존 규칙대로 첫 구성도가 함께 생긴다.
- `list_diagrams(project_id)`
- `create_diagram(project_id, name)`

**읽기**
- `get_diagram(diagram_id)` — 한 번에 준다.
  - 최신 버전 번호
  - 영역, 노드, 연결, 가정. 망 영역의 종류와 그 출처(추정·확정), 망연계 노드의 "AI 추정" 여부도 들어간다.
  - 흐름과 끊긴 흐름
  - 경고(망연계 예상 포함), 빠진 정보
  - 브라우저에서 열 주소
- `list_versions(diagram_id)` — 변경 이력(번호, 시각, 출처, 요약 한 줄).

**고치기**
- `apply_commands(diagram_id, base_version, commands[], summary, dry_run?)`
  - **명령은 대화 기능과 같은 명령을 쓴다.** 노드·연결·영역·가정·흐름 명령, 망 지식 설계의 `set_zone_type`과 `add_node`의 `guess`가 들어간다. 서버 전용 명령(`set_link_guess`)과 `say`는 받지 않는다.
  - **전부 적용하거나 하나도 적용하지 않는다. (제 판단)** 하나라도 틀리면 아무것도 저장하지 않는다. 돌려주는 것은 몇 번째 명령이 왜 틀렸는지 쉬운 말로 적은 목록이다(예: "3번: parent 영역 vpc-1 이 없어요"). 반쯤 그려진 구성도가 남지 않게 하려는 것이다.
  - **덮어쓰기 막기. (제 판단)** `base_version`이 지금 최신 버전과 다르면 적용하지 않는다. "구성도가 바뀌었어요(지금 버전 N). get_diagram 으로 다시 읽어 주세요"를 돌려준다.
  - `dry_run`이면 검사만 하고 결과(적용됐다면 생길 경고·빠진 정보)를 돌려준다. 저장하지 않는다.
  - **성공하면 대화 차례 끝과 같은 정리를 한다.** 차례에 비게 된 영역 정리, 망연계 추정의 대신한 연결 기록, 흐름 단계 나누기, 코드 규칙 경고 점검이다. 경고 점검은 Clef·Qwen을 부르지 않고 코드 규칙과 망 지식 판정만 한다. **(제 판단)** 정리가 끝나면 버전 하나로 저장한다.
  - 돌려주는 것: 새 버전 번호, 바꾼 곳 수, 새로 생긴 경고, 빠진 정보 목록, 망연계 예상, 브라우저 주소. Claude는 이걸 보고 "IP 3개가 비어 있어요" 같은 질문을 사용자에게 이어 갈 수 있다.
  - `summary`는 이력에 남길 한 줄이다(80자). 비면 "Claude Code에서 N곳 바꿈".
  - **흐름 명령이 섞인 경우. (사용자: 나안)**
    - **"전부 아니면 전무"는 흐름까지 넓힌다.** 흐름 명령도 구성 명령을 다 적용한 상태에 대해 먼저 끝까지 검사한다. 하나라도 거절되면 구성·흐름 모두 저장하지 않는다. 검사를 통과하면 버전 저장과 흐름 저장을 한 트랜잭션으로 한다.
    - **덮어쓰기 막기는 흐름에 적용하지 않는다.** `base_version`은 구성만 지킨다. 브라우저에서 흐름을 고치는 일(이름 바꾸기·삭제·확인·단계 지우기)은 드물기 때문이다. `get_guide`에 "흐름은 버전과 따로 저장되며, 고치기 전에 get_diagram 으로 최신 흐름을 읽으라"고 적는다.
    - **흐름만 바꾼 호출은 버전을 만들지 않는다.** 대화 차례와 같다. 결과에는 새 버전 번호 대신 바뀐 흐름 수를 준다. 이력에는 남지 않는다. 브라우저는 흐름 탭만 다시 불러온다(6절).
- `restore_version(diagram_id, base_version, number)` — 예전 버전으로 되돌린다. 새 버전이 하나 생긴다. **(제 판단)**
  - 고치기와 같이 구성도 잠금을 쓰고 `base_version`을 검사한다. 기존 브라우저 되돌리기(`restoreVersion`)에는 둘 다 없으므로 MCP 경로에서 더한다.
  - 대화 기록에 "vN로 되돌림" 메시지를 남기지 않는다. 기존 `restoreVersionWithMessage`는 쓰지 않는다.
  - 출처는 `restore`이고, 이력에는 "되돌리기 · Claude Code에서"로 보인다. 그래서 버전에 "어디서" 칸(예: `via: "mcp"`)을 하나 더하고, `mcp` 출처 버전에도 같은 칸을 쓴다.
  - 흐름은 되돌아가지 않는다(망 지식 설계 6). 결과에 되돌린 뒤 끊긴 흐름 수와 이름을 준다.

**넣지 않는 도구 (사용자)**
- 프로젝트·구성도 삭제
- 망 지식 편집, 계정 설정
- 노드 설명 생성처럼 InfraSketch의 Qwen을 쓰는 기능

되돌리기 어려운 일은 브라우저에서만 한다.

### 5. 기록과 동시 작업

- **기록.** MCP로 만든 버전의 출처는 새 값 `mcp`다. 이력 탭에는 "Claude Code에서"와 summary 한 줄이 보인다.
  - AI가 만든 것으로 보므로 망 종류·망연계 추정은 지금처럼 "AI 추정" 표시가 붙는다.
  - 구성도 대화 기록에는 메시지를 남기지 않는다. **(제 판단)**
- **동시 작업.** 쓰기 도구는 기존 구성도 잠금(`withDiagramLock`)을 쓴다. 브라우저 대화 차례가 돌고 있으면 "지금 다른 변경이 진행 중이에요. 잠시 뒤 다시 시도해 주세요"를 돌려준다.

### 6. 브라우저에서 보기 (사용자: "어렵지 않으면 시각 효과도")

- 그 구성도를 브라우저에 열어 두었다면, 새 버전이 생긴 것을 몇 초 안에 알아채서 불러온다. 탭이 보일 때만 확인한다. **(제 판단: 짧은 간격으로 최신 버전 번호를 확인하는 방식으로 충분하다)**
- 새로 생긴 노드·연결은 지금 대화 기능의 나타나는 효과로 보이고, 지워진 것은 사라지는 효과로 보인다.
- 흐름만 바뀐 경우(버전 없음)는 흐름 탭을 열어 두었을 때 흐름 목록만 다시 불러온다. 알아채는 방법은 만드는 사람이 정한다(예: 흐름 최종 수정 시각).
- 사용자가 브라우저에서 무언가 입력하는 중이면 끼어들지 않는다. "Claude Code가 구성도를 바꿨어요 [불러오기]"만 띄운다. **(제 판단)**
- 열어 두지 않았으면 다음에 열 때 최신 모습이 보인다.

## 하지 않는 것

- 삭제, 망 지식 편집, 계정 설정 도구 **(사용자)**
- MCP 경로에서 InfraSketch의 Qwen·Clef 쓰기
- OAuth 로그인. 키 방식만 둔다.
- 팀·프로젝트 단위 권한. 키는 계정 단위다.
- 앱 배포(사내 서버). 별도 과제로 미뤄져 있다.
- 노드 질문, 설명, 흐름 제안 같은 다른 AI 기능을 MCP로 여는 일
- 코드 저장소를 InfraSketch가 직접 읽는 기능. Claude Code가 읽는다.

## 실패로 보는 것

- Claude Code가 그린 구성도가 대화로 그린 것과 다른 규칙으로 그려져, 같은 앱 안에서 모양이 제각각이다. 예: 이중화 묶음 없음, 망 경계 노드 빠짐.
- 명령 일부만 적용되어 반쯤 그려진 구성도가 저장된다.
- 브라우저에서 고친 내용을 Claude Code가 모르고 덮어쓴다.
- 거절 이유가 모호해서 Claude가 같은 실수를 되풀이한다.
- 키 하나로 다른 계정의 프로젝트가 보인다. 또는 키 원문이 DB·로그에 남는다.
- 그리기 규칙을 고쳤는데 Qwen과 Claude Code 중 한쪽에만 반영된다.
- 브라우저 화면이 Claude Code 변경 때문에 사용자가 입력하던 것을 날린다.

## 제약

- 망 지식 설계와 앞선 설계의 제약을 따른다. 명령 검사·적용은 기존 `parseCommand`·`applyCommand`를 그대로 쓴다. 새 검사 규칙을 MCP 쪽에 따로 만들지 않는다.
- 화면 규칙(1단계), 쉬운 한국어, drizzle 마이그레이션(개발 DB 적용·푸시는 사용자 요청 시), 문서 사이트 동기화를 따른다. 문서 사이트에는 MCP 도구 표와 키 데이터 모델을 더한다.
- `get_guide` 결과는 Claude가 한 번에 읽을 수 있는 크기로 둔다. 목표는 약 2만 자 이하다. **(제 판단)**

## 만드는 사람에게 맡기는 것

- MCP SDK 버전과 Next.js 라우트에서 붙이는 방법. stateless Streamable HTTP를 지킨다.
- 키 형식, 해시 방식, 테이블 모양. 원문은 저장하지 않는다.
- 공용 그리기 규칙 모듈의 이름과 나누는 방식. Qwen 프롬프트가 지금과 같은 글을 만들어야 한다(회귀 테스트로 확인).
- 거절 이유를 쉬운 말로 바꾸는 방식. 기존 `applyCommand` 오류 글을 바탕으로 한다.
- 브라우저가 새 버전을 알아채는 간격과 방식, 효과를 다시 쓰는 방법
- 도구 결과의 정확한 JSON 모양
- 테스트 구성
  - 통합: MCP 클라이언트로 도구 호출, 키 검사, 덮어쓰기 거절, 전부 아니면 전무
  - E2E: 키 화면, 열어 둔 구성도에 변경이 나타남
