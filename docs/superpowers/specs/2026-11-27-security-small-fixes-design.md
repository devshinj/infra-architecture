# 보안 작은 고침 (개선 묶음 A)

2026-11-27 서비스 검토에서 나온 보안 항목 가운데, 작고 서로 독립인 것을 한 묶음으로 고친다.
운영 안전망(CI·Docker 배포·백업)과 자원 한도(잠금 연결·길이 상한)는 다음 묶음(B, C)에서 따로 다룬다.

## 왜

- 로그인 없이 부를 수 있는 길에서 서버 CPU 를 묶거나 횟수 제한을 넘길 수 있다.
- 비밀번호를 재설정해 계정을 되찾아도, 그 전에 만든 MCP 키로 구성도를 계속 읽고 고칠 수 있다.
- 운영 설정 실수(짧은 `AUTH_SECRET`, 빠진 `APP_URL`)를 서버가 말없이 받아들인다.

## 목표와 범위 밖

- 목표: 아래 아홉 항목. 화면 흐름은 그대로 두고, 재설정 뒤 안내 문구 한 줄만 는다.
- 범위 밖: CSP(깨지는 곳을 먼저 조사해야 한다), HSTS(HTTPS 는 앞단 몫), 가입 때 이메일 확인,
  아이디 10번 틀리면 15분 잠기는 한계(2026-11-17 에 받아들인 것).
- 하지 말 것: 지금 도는 운영 서버의 동작을 설정 없이 바꾸는 것. 그래서 프록시 설정은 값을 줄 때만 동작을 바꾼다.

## 접근

검토 때 정한 것:

| 결정 | 고른 것 | 다른 길과 버린 이유 |
|---|---|---|
| 재설정 뒤 MCP 키 (사용자 결정, 2026-11-27) | 모두 지운다 | 유지하고 알리기 — 주인이 모르는 키를 못 막는다. 그대로 두기 — 2026-11-17 선택이었으나, 남의 이메일로 먼저 가입해 키를 만들어 두는 경우를 그때는 따지지 않았다. |
| 로그인 제한 순서 | 기록을 먼저 넣고 센다 | 아이디별 잠금(트랜잭션 advisory lock) — 같은 효과에 잠금 경로가 하나 더 생긴다. |
| 요청한 쪽 IP | `TRUSTED_PROXY_HOPS` 를 줄 때만 오른쪽에서 세고, 없으면 지금처럼 첫 값 | 기본을 바로 바꾸기 — 프록시가 두 겹이면 모든 사용자가 한 IP 로 묶여 함께 막힌다. 프록시 구성을 모르는 채로 기본을 바꾸지 않는다. |
| 운영 설정 검사 위치 | 서버를 켤 때(`instrumentation.ts`) | `env.ts` 스키마에서 — `next build` 때도 걸려, 비밀값 없이 이미지를 빌드할 수 없게 된다. |

## 항목

1. **재설정 제출** (`reset.ts`): 토큰이 쓸 수 있는지 먼저 조회하고, 아니면 bcrypt 를 돌리지 않고 끝낸다.
   한 번만 쓰이게 하는 조건부 UPDATE 는 그대로 둔다(조회와 UPDATE 사이에 쓰인 토큰은 거기서 걸린다).
2. **횟수 제한 선점** (`rateLimit.ts` `claimAttempt`): 기록을 먼저 넣고 센다. 한도를 넘으면 내 기록을 지우고 막는다
   (막힌 시도는 세지 않는 지금 규칙 유지). 동시에 몰려도 통과하는 수는 남은 한도를 넘지 못한다.
   - 로그인: 아이디·IP 둘 다 선점. 성공하면 아이디 기록 전부와 내 IP 기록을 지운다.
   - 재설정 요청: 주소별 선점.
   - 가입: IP 선점 뒤, 계정을 만들지 못하면 내 기록을 지운다(만든 계정만 세는 규칙 유지).
   - IP 를 모르는(`unknown`) 로그인은 IP 한도를 세지 않는다. 지금은 모르는 요청이 한 통에 묶여,
     프록시 없이 띄우면 30번 틀린 누군가가 모두의 로그인을 막는다. 가입은 이미 이렇게 한다. (내 판단)
3. **재설정 때 MCP 키 폐기**: 재설정 트랜잭션 안에서 그 계정의 `mcp_keys` 를 지운다.
   지운 키가 있으면 로그인 화면 안내에 "MCP 연결 키는 모두 지웠어요" 를 덧붙인다.
4. **운영 설정 검사** (`env.ts` `productionProblems`, `src/instrumentation.ts`): `NODE_ENV=production` 으로 켤 때
   `AUTH_SECRET` 이 32자 미만이거나 `APP_URL` 이 비어 있으면 이유를 적고 켜지 않는다.
   SMTP·`TRUSTED_PROXY_HOPS` 가 없으면 경고만 남긴다.
5. **재설정 링크 기록**: 운영에서 SMTP 가 없으면 링크를 로그에 찍지 않고 "보내지 못함"만 남긴다.
   메일 서버 없이 운영해야 하면 `RESET_LINK_LOG=1` 로 켠다(개발·테스트는 지금처럼 찍는다).
6. **요청한 쪽 IP** (`clientIp`): `TRUSTED_PROXY_HOPS=n` 이면 `x-forwarded-for` 를 오른쪽에서 n번째로 읽는다
   (값이 n개보다 적으면 맨 왼쪽). `0` 이면 헤더를 믿지 않는다(`unknown`). 값이 없으면 지금처럼 첫 값.
7. **보안 헤더** (`next.config.ts`): `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
   `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `Permissions-Policy`(카메라·마이크·위치 끔),
   `X-Powered-By` 제거.
8. **의존성**: 호환 범위 안에서 `npm audit fix`. 남는 것은 보고한다.
9. **개발 compose**: DB 포트를 `127.0.0.1` 에만 연다.

## 확인

- 통합 테스트: 토큰이 틀리면 해시를 부르지 않는다, 동시에 30번 틀려도 기록·통과 수가 한도 안이다,
  재설정 뒤 키가 지워지고 `verifyMcpKey` 가 null, `clientIp` 세 가지 설정.
- 단위 테스트: `productionProblems`, 보안 헤더 목록, 운영에서 링크를 찍지 않는다.
- `npm test`, `npm run test:int`, `npm run lint`, `npx tsc --noEmit`, `npm run build`.

## 배포할 때 볼 것

- 운영 `.env` 의 `AUTH_SECRET` 이 32자 미만이면 서버가 켜지지 않는다. 먼저 확인한다.
- 운영에 SMTP 가 없으면 재설정 링크가 더는 로그에 나오지 않는다. 필요하면 `RESET_LINK_LOG=1`.
- 앞단 프록시가 한 겹이면 `TRUSTED_PROXY_HOPS=1` 을 넣는다.
- 재설정한 사용자는 MCP 키를 다시 만들어야 한다.
