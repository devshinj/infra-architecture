# 학습 모드

날짜: 2026-11-19. 표기: (사용자) 는 대화에서 사용자가 정한 것, (설계자) 는 설계자가 정한 것으로 검토 때 바꿀 수 있다.

## 왜

지금 앱은 "아는 만큼 말하면 그려 준다". 인프라를 잘 모르는 사람은 무엇을 말해야 할지부터 막힌다. 학습 모드는 누구나 아는 서비스(쇼핑몰·메신저 등)의 완성된 구성도를 가이드를 따라 **자기 손으로 말을 입력해 한 단계씩 만들어 보게** 한다. 만드는 동안 왜 이 부품이 필요한지, 흐름·망 특성·연계 구간·주의할 점을 듣는다. 구성도 지식과 이 도구에 말 거는 법을 함께 익힌다. (사용자)

## 목표

- 주제를 고르고 환경을 확정한 뒤, 가이드 단계마다 학습자가 채팅에 요청을 입력해 구성도를 완성한다. (사용자)
- 완성본은 미리 설계한 구성도와 같다. 학습자의 말은 "이번 단계 의도와 맞는가"만 판정하고, 그리는 것은 미리 쓴 대본이 한다. (사용자, 방식 1)
- 학습 구성도의 노드·연결은 정보가 빠짐없이 채워져 있다(가상의 값). 학습자는 설명 탭을 이해할 때까지 볼 수 있다. (사용자)
- 채팅 설명은 짧고 명확하다. (사용자)
- 끝난 구성도는 일반 구성도로 남아 자유롭게 고칠 수 있고, 중간에 나가면 멈춘 단계부터 이어서 한다. (사용자)
- 주제는 실제 서비스를 본뜬 여러 편이고, 온프레미스·클라우드 환경으로 나뉜다. 환경은 먼저 확정한다. (사용자)

## 하지 않는 것

- 학습자의 말대로 AI 가 자유롭게 그리고 가이드가 맞추는 방식(방식 2·3). 고르지 않았다.
- 진행 중인 구성도를 그 자리에서 다른 환경으로 변환하기. 다른 환경은 새 구성도로 다시 만든다. (설계자)
- 점수·등급·퀴즈·학습 이력 통계.
- 사용자가 직접 가이드를 쓰는 화면. 가이드는 코드에 든 대본이다.
- 순서를 건너뛴 요청을 알아보고 "그건 N단계 뒤"라고 짚어 주기. 첫 출시는 이번 단계 안내만 한다. (설계자)

## 실패로 보는 것

- 가이드가 사실처럼 틀린 내용을 가르친다. 그래서 가르치는 글은 모두 사람이 검토한 대본에서만 나온다(학습자 질문에 대한 답만 예외로 Qwen 이 쓴다).
- 단계 설명이 길어 읽지 않게 된다(제품 원칙 1).
- 실제 회사의 내부 구성인 것처럼 보인다. 대본은 "이런 서비스를 만든다면 흔히 쓰는 구성"이고 화면에 그렇게 적는다. 제목은 회사 이름이 아니라 종류로 쓴다("대형 쇼핑몰"). (설계자)
- 자기 말로 바꿔 입력했는데 번번이 틀렸다고 한다.

## 주제와 출시 순서

| 주제 | 배우는 핵심 (설계자 제안, 사용자가 반대하지 않음) | 먼저 쓸 환경 (설계자) |
|---|---|---|
| 쇼핑몰 | 3계층, 이중화, 결제 외부 연동, 트래픽 몰림 대응(캐시·대기열) | 온프레미스·클라우드 둘 다 |
| 메신저 | 끊기지 않는 실시간 연결, 메시지 큐, 푸시 알림 | 클라우드 |
| 배달앱 | 고객·가게·라이더 세 앱, 위치 추적, 주문 상태 알림 | 클라우드 |
| 동영상 스트리밍 | 업로드→변환→저장→CDN, 큰 파일의 흐름 | 클라우드 |
| 영상관제시스템 | 현장 카메라→수집→저장→관제, 폐쇄망·망 경계 | 온프레미스 |
| 여러 SNS 로그인 연동 앱 | 카카오·네이버·구글 로그인 흐름, 인증 서버, 토큰 | 클라우드 |
| 외부 연계가 많은 중계시스템 | 연계 구간, 망연계, 기관별 연결 방식, 장애 격리 | 온프레미스 |

- **1차**: 엔진 + 주제 고르는 화면 + 쇼핑몰 두 벌(온프레미스·클라우드). 사용자가 써 보고 형태를 확정한다. (설계자 제안, 사용자 동의)
- **2차**: 나머지 여섯 주제를 위 환경으로 한 벌씩. 반대 환경은 그 뒤.
- 이 문서와 이어지는 구현 계획은 1차 범위다. 2차 대본은 1차가 확정된 뒤 따로 쓴다.
- 대본 초안(단계·가상 값·해설)은 설계자가 쓰고 사용자가 검토한다.

## 방법 (사용자 선택: 1)

학습자의 말이 이번 단계와 맞는지 판정하는 방법 셋을 견주었다.

1. **Clef 판정 + 키워드 예비 (선택)**: Clef 에 "이 말이 '○○'을 요청하는가"를 예/아니오(noul)로 묻는다. Clef 가 꺼졌거나 답이 없으면 대본의 핵심 단어로 판정한다. 빠르고(3초 상한), 자기 말로 바꿔도 통하고, AI 서버 없이도 학습이 된다. 틀렸을 때 안내는 대본의 고정 문구다.
2. Qwen 판정: 맞춤 안내를 쓰지만 단계마다 몇 초씩 걸리고, 대본에 없는 말을 지어낼 수 있고, AI 서버가 없으면 학습이 안 된다.
3. 키워드만: 표현만 달라도 틀렸다고 해 "말하는 법 익히기"와 어긋난다.

## 사용자가 보는 모습

### 들어가기

- 왼쪽 사이드바에 "학습 모드" 항목. 누르면 주제 고르는 화면(`/learn`)이 열린다. (설계자)
- 주제 카드: 이름, 한 줄 소개, 배우는 핵심, 단계 수, 준비된 환경 표시. 화면 위에 "실제 회사의 구성이 아니라, 이런 서비스를 만들 때 흔히 쓰는 구성입니다" 한 줄.
- 주제를 고르면 "학습" 프로젝트(없으면 만든다)에 그 주제 이름의 빈 구성도를 만들고 그 구성도 화면으로 간다. 같은 이름이 있으면 기존 이름 겹침 규칙(`copyName`)을 따른다. (설계자)
- 주제 화면에는 진행 중인 학습("이어서 하기")과 끝낸 학습도 보인다.

### 첫 대화: 환경 확정

- 가이드의 첫 메시지가 환경을 묻는다. 온프레미스와 클라우드에서 무엇이 달라지는지 두세 줄로 말하고, 고를 수 있는 칩 두 개를 보인다. 학습자는 칩을 누르거나 말로 답한다("온프레미스로 할게"). 판정은 키워드로 한다(Clef 를 쓰지 않는다). (설계자)
- 한쪽 환경만 준비된 주제는 그 사실을 알리고 확인만 받는다.
- 확정하면 `set_assumption environment` 가 적용되고 그 환경의 대본 1단계로 간다.

### 단계

채팅 패널 위쪽에 단계 카드가 붙는다.

```
┌ 학습: 대형 쇼핑몰 (온프레미스)            3 / 12 ┐
│ 이번 단계: WAS 를 두 대로 이중화하기              │
│ 이렇게 말해 보세요: "WAS 두 대를 이중화해서 넣어 줘" [입력창에 넣기] │
│                                   [학습 그만두기] │
└───────────────────────────────────────────────┘
```

- 학습자가 입력한다. 예시 문장 그대로여도, 자기 말이어도 된다.
- **맞으면**: 대본의 명령이 평소 대화처럼 하나씩 그려지고, 가이드가 설명(`say`)을 말한다. 그 아래 접힌 해설 칩이 붙는다(흐름 / 망 특성 / 연계 구간 / 주의). 누르면 펼쳐진다. 이어서 다음 단계 카드로 바뀐다.
- **안 맞으면**: 아무것도 그리지 않고 그 단계의 안내(`miss`)를 말한다. 수량처럼 흔한 어긋남은 대본에 전용 안내를 둘 수 있다("이번에는 두 대로 합니다. 세 대는 …").
- **질문이면**("L4 가 뭐야?"): 단계를 넘기지 않고 평소 질문 답변(Qwen)으로 답한다. AI 서버가 없으면 평소와 같은 안내 문구가 나온다.
- 단계마다 변경 이력에 한 줄이 남는다(요약은 단계 이름).

### 끝

- 마지막 단계 뒤 완료 메시지: 만든 것 한 줄 요약, "다른 환경이라면 무엇이 무엇으로 바뀌는지" 짧은 표(대본에 든 글), "이제 자유롭게 고쳐 보세요". 다른 환경 대본이 있으면 "다른 환경으로 다시 만들기" 버튼(새 구성도를 만들고 환경이 이미 확정된 채 시작한다).
- 그 뒤 이 구성도는 일반 구성도다. 대화는 평소 경로로 간다.

### 그만두기·이어서 하기·되돌리기

- "학습 그만두기": 확인 뒤 그 시점 구성도가 일반 구성도가 된다. 이어서 하기는 안 된다. (설계자)
- 나갔다 돌아오면 같은 단계 카드가 보인다. 대화 기록도 그대로다.
- 학습 중 이력에서 이전 단계 버전으로 되돌리면 단계도 그 버전 다음 단계로 돌아간다. (설계자)
- 학습 중에는 가이드 밖 변경을 받지 않는다. **허용 목록 방식**이다(설계자): 되는 것은 위치 옮기기·자동 정렬·흐름 재생·설명 보기·이미지 저장·이력 되돌리기·구성도 복제·이름 바꾸기·지우기뿐이고, 구성도 상태·흐름·가정·경고 무시·망 종류·망연계를 바꾸는 나머지(샘플 불러오기, MCP 쓰기, 값 고치기, 흐름 지우기·이름 바꾸기·"맞아요", 흐름 제안, 설명 "다시 쓰기" 등)는 모두 "학습 중에는 바꿀 수 없어요. 학습을 그만두면 바꿀 수 있어요"로 막는다.
- 복제본은 일반 구성도다(학습 상태를 복사하지 않는다).
- 구성이 바뀐 뒤 흐름이 없으면 자동으로 도는 흐름 제안(`/flows/suggest`)은 학습 중 서버에서 막는다. 흐름은 대본이 넣는다.

## 구조

### 대본 (`src/domain/guides/`)

샘플(`src/domain/samples/`)처럼 코드에 든 자료다. 샘플의 짧은 도우미(`dsl.ts` 의 `group`·`node`·`edge`·`flow`·`assume`)를 그대로 쓴다.

```ts
type GuideEnv = "onprem" | "cloud";

interface Guide {
  id: string;                 // "shop"
  title: string;              // "대형 쇼핑몰"
  intro: string;              // 카드 한 줄
  learns: string[];           // 배우는 핵심
  envIntro: string;           // 첫 대화의 환경 설명
  variants: Partial<Record<GuideEnv, GuideVariant>>;
}

interface GuideVariant {
  steps: GuideStep[];
  outro: string;              // 완료 요약
  otherEnv?: { from: string; to: string }[]; // "L4 장비 → 로드밸런서 서비스" 표
}

interface GuideStep {
  id: string;
  goal: string;               // 카드 제목이자 Clef 판정 질문에 넣는 목표
  example: string;            // "이렇게 말해 보세요"
  keywords: string[][];       // 예비 판정: 묶음마다 하나 이상 들어 있어야 맞음
  conflicts?: { pattern: string[]; reply: string }[]; // 흔한 어긋남 전용 안내(수량 등)
  commands: Command[];        // 구성·가정·흐름 명령
  say: string;                // 그린 뒤 설명
  notes?: { kind: "flow" | "net" | "link" | "caution"; text: string }[];
  miss: string;               // 안 맞을 때 안내
  explains?: Record<string, AuthoredExplanation>; // 이 단계에서 생긴 노드·영역·연결의 설명 탭 글
}
```

- 길이 한도(설계자): `say` 160자, `notes` 단계당 최대 3개·각 120자, `miss` 100자, `goal` 30자. 테스트가 지킨다.
- 가상 값: IP 는 사설 대역, hostname·VIP·방화벽 규칙은 지어낸 값. 주제 화면과 첫 대화에 "값은 예시입니다"라고 적는다.
- 환경 축은 `GuideEnv` 둘뿐이다. 클라우드 대본의 사업자(AWS 등)는 대본이 정한다.

### 설명 탭 글 (설계자)

설명 탭의 "역할·왜 골랐는지(ADR)"는 평소 Qwen 이 만든다. 학습 구성도에서는 대본에 미리 쓴 글(`explains`)을 설명 저장소(`explanations`)에 넣는다. 가르치는 글을 검토된 것으로 유지하고, AI 서버가 없어도 설명 탭이 채워지게 하려는 것이다.

- `AuthoredExplanation` 은 기존 설명 타입(`NodeExplanation`·`GroupExplanation`·`EdgeExplanation`)에서 대본이 쓰는 칸이다: 노드는 용어·정의·역할·ADR 4칸, 영역은 거기에 경계, 연결은 기존 4칸. 길이는 기존 한도(`LIMITS`)를 따른다.
- 정의(용어 뜻)는 대본에 쓰거나, 비우면 **기본 사전(seed)** 에서 읽는다. 계정의 용어 사전은 사용자가 고치거나 지울 수 있어 학습 글의 출처로 쓰지 않는다. seed 에도 없는 용어는 대본에 정의를 써야 한다(테스트).
- 학습 중에는 설명 "다시 쓰기"를 막는다(Qwen 글이 대본 글을 덮지 않게).
- 설명 저장소는 서명(signature)이 바뀌면 다시 만든다. 이웃이 붙으면 서명이 바뀌므로, 학습 중에는 단계를 적용할 때마다 대본에 글이 있는 대상을 **현재 서명으로 다시 저장**한다.
- 학습이 끝나거나 그만둔 뒤 학습자가 구성을 바꾸면 평소처럼 Qwen 이 다시 만든다.
- 대본의 모든 노드·영역·연결은 `explains` 가 있어야 한다(테스트). 연결 글이 없으면 눌렀을 때 Qwen 이 만들게 되어 "가르치는 글은 대본에서만"이 깨진다.

### 대본이 넣은 것은 확정으로 저장한다 (설계자)

평소 적용 함수는 가정을 미확정, 망 종류를 "AI 추정", 흐름을 "AI 제안"으로 남긴다. 학습 중에는 확정 조작을 막으므로 그대로면 풀 수 없는 미확정 표시가 끝까지 남는다. 그래서 가이드 차례는 대본 명령을 적용한 뒤 샘플(`buildSample`)처럼 고친다.

- 망 종류: `source: "user", confirmed: true`.
- 가정: 확정. 끝난 뒤 바꾸려면 평소처럼 가정 칩에서 사람이 바꾼다(확정된 가정은 AI 가 바꾸지 못한다).
- 흐름: 검토된 것(`reviewed: true`)으로 저장한다.
- 대본에는 망연계 추정(`set_link_guess`)을 쓰지 않는다. 연계 구간은 대본이 중계 노드와 연결로 직접 그린다.

### 망 지식 (설계자)

빠진 정보와 망연계 경고는 계정의 망 지식에 따라 달라진다. 대본 테스트는 기본 망 지식(seed) 기준으로 "빠진 정보 0·경고 고정"을 지킨다. 실행 때는 평소처럼 계정의 망 지식을 쓴다. 망 지식을 고친 계정에서는 경고가 대본과 다를 수 있고, 그것은 그 계정의 규칙이 반영된 결과로 둔다. 대본 글은 특정 경고가 뜬다고 단정해 말하지 않는다.

### 진행 상태 (새 표 `guide_runs`)

| 칸 | 뜻 |
|---|---|
| diagram_id | 구성도(유일). 구성도를 지우면 함께 지워진다 |
| guide_id | 주제 |
| env | 확정 전 null, 뒤에 `onprem`·`cloud` |
| step | 다음에 할 단계 번호(0 부터) |
| step_versions | 단계별로 만든 버전 번호 목록(되돌리기 때 단계를 맞춘다) |
| status | `active`·`done`·`quit` |

- `active` 인 구성도가 "학습 중"이다. 대본이 코드에서 사라졌거나 단계 수가 줄어 `step` 이 범위를 넘으면 `quit` 로 바꾸고 일반 구성도로 연다.
- 흐름은 버전과 따로 저장돼 되돌려도 남는다. 그래서 학습 중 이전 단계로 되돌리면 그 뒤 단계가 넣은 흐름을 지운다(어느 단계가 어느 흐름을 넣는지는 대본에서 안다). 그래도 이미 있는 흐름 id 로 온 대본의 `add_flow` 는 거절하지 않고 덮어쓴다.
- 대본을 고쳐 배포하면 진행 중인 학습의 뒤 단계 명령이 앞에서 만든 것과 안 맞을 수 있다. 단계 적용에서 명령이 거절되면 그 학습을 `quit` 로 바꾸고 "가이드가 바뀌어 이어갈 수 없어요. 처음부터 다시 해 주세요"를 알린다. (설계자)

### 한 차례의 흐름 (`src/server/guide/`)

대화 경로(`POST /api/diagrams/[id]/chat`, `runChatTurn`)는 그대로 두고, 구성도 잠금을 얻은 뒤 `guide_runs` 가 `active` 면 평소 차례 대신 가이드 차례를 돌린다. 이벤트(`ChatEvent`)·메시지 저장·버전 만들기·잠금은 기존 것을 쓴다. 학습 대화는 기본 대화(session 없음)에만 쌓는다. 학습 중에는 새 대화 세션 만들기를 숨긴다.

1. 사용자 메시지를 저장한다.
2. 환경 미확정이면 키워드로 환경을 읽는다. 읽히면 확정하고 1단계 카드를 내보낸다. 안 읽히면 다시 묻는다.
3. 단계 판정:
   - `conflicts` 에 걸리면 그 안내.
   - Clef `decide` 한 번에 noul 질문 둘: "이 말이 '{goal}'을 요청하는가", "이 말이 무언가를 묻는 질문인가". 상한 3초, 재시도 없음.
   - 맞음 확률이 기준 이상이면 **맞음**. 아니고 질문 확률이 기준 이상이면 **질문**. 둘 다 아니면 **안 맞음**. 기준값은 평가로 정한다(시작값 0.6).
   - Clef 가 없거나 답이 없으면: `keywords` 가 맞으면 맞음, 물음표·"뭐야/왜/어떻게"류면 질문, 아니면 안 맞음.
4. 맞음: 대본 명령을 기존 적용 함수로 적용하며 명령 이벤트를 내보내고(캔버스 애니메이션은 평소와 같다), 버전을 만들고(요약 = 단계 이름), 대본 설명을 저장소에 넣고, `say`·`notes` 를 메시지로 저장하고, `step` 을 올린다. 마지막 단계면 `done` 으로 바꾸고 완료 메시지를 보낸다.
5. 질문: 기존 질문 답변 경로를 구성도를 바꾸지 않는 모드로 부른다. 단계는 그대로다.
6. 안 맞음: `miss` 를 메시지로 저장한다.

메시지 메타에 `guide: { step, kind: "step" | "miss" | "env" | "done", notes? }` 를 넣어 화면이 해설 칩과 완료 표를 그린다.

### 화면 (`src/ui/guide/`)

- `/learn` 주제 화면, 사이드바 항목, 채팅 패널 위 단계 카드, 메시지의 해설 칩·완료 표, 환경 칩, 그만두기 확인.
- 학습 중 막힌 조작은 버튼을 숨기지 않고 눌렀을 때 이유를 말한다(설명 패널 값 고치기 등).
- 기존 디자인 문서(DESIGN.md)와 컴포넌트를 따른다. 키보드로 전 과정을 마칠 수 있어야 한다.
- 구성도 목록에서 학습 중인 구성도는 작은 표시("학습 3/12")를 붙인다.

## 검증

- 대본 단위 테스트(모든 대본·환경): 빈 상태에서 단계 순서대로 명령이 하나도 거절되지 않는다 / 끝 상태에서 빠진 정보(`computeMissing`)가 0 이다 / 끝 상태의 경고 목록을 고정한다(의도한 경고만) / 흐름 명령이 저장된다 / 글 길이 한도 / 모든 노드·영역에 설명 글이 있다 / 각 단계의 `example` 이 그 단계 `keywords` 로 맞음 판정된다.
- 가이드 차례 단위 테스트: 맞음·안 맞음·질문·환경 확정·완료·Clef 없음·명령 거절(→ quit)·되돌리기 뒤 단계.
- 판정 평가(`npm run eval:guide`, 기존 `eval:intent` 방식): 단계마다 맞는 문장(자기 말 표현 포함)과 반대 문장(다른 단계 요청·수량 다름·질문)을 넣어 Clef 판정 정확도를 본다. 사내망 안에서만 돈다. 흔들림은 기존 관행대로 여러 번 돌려 본다.
- E2E 한 편: 주제 고르기 → 환경 → 두 단계 → 나갔다 오기 → 이어서 → 그만두기.

## 만드는 사람에게 남기는 것

- 가이드 차례를 `pipeline.ts` 안 분기로 둘지 따로 둔 함수로 부를지, 질문 답변을 어느 함수로 재사용할지.
- 학습 중 막는 조작들의 검사 위치(서버 액션·MCP 도구 공통 함수).
- `step_versions` 대신 버전 쪽에 단계를 적는 방식 등 같은 동작을 내는 저장 모양.
- 단계 카드·칩의 구체 모양(DESIGN.md 범위 안).
- 쇼핑몰 두 벌의 단계 나누기와 글: 계획 단계에서 초안을 쓰고 사용자가 검토한다. 한 벌에 10~14단계를 기준으로 한다.

## 사용자 확인이 필요한 설계자 판단 (요약)

1. 설명 탭 글(정의·역할·ADR)을 노드·영역·연결 모두 대본에 미리 쓴다(AI 생성 대신). 검토할 글이 그만큼 늘어난다.
6. 대본이 넣은 가정·망 종류·흐름은 "확정"으로 저장한다.
7. 학습 중에는 허용 목록(보기·위치·정렬·되돌리기·복제 등) 밖의 변경을 모두 막고, 자동 흐름 제안과 설명 "다시 쓰기"도 막는다.
2. 학습 구성도는 "학습" 프로젝트에 자동으로 만든다.
