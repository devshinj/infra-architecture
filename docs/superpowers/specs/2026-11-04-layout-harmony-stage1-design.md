# 구성도 배치 조화 1단계 — 선택 강조와 선 간격

날짜: 2026-11-04 · 상태: 초안 — 검토자 질문 반영, 사용자 승인 전

## 왜 하는가

이 작업은 구성도 배치 조화 프로젝트 4단계 가운데 첫 단계다. 순서는 사용자가 정했다.
1. 선택 강조·선 간격
2. 외부 서비스 정리
3. 배치 모양
4. 규모 대응

사용자가 말한 문제는 세 가지다.
- 노드와 영역이 늘수록 읽기 어려워진다.
- 선이 많아지면 겹친 줄이 복잡해진다.
- 노드를 골라도 무엇과 이어졌는지가 "확 느껴지지" 않는다.

구성도 크기는 정해 두지 않는다. 사용자는 "가늠할 수 없다, 여러 외부 서비스와 결합할 수도 있다"고 했다. 그래서 노드가 10개일 때와 200개일 때 모두 버텨야 한다.

실측은 1440×900 화면에서 했다. 측정 도구는 `C:\Users\devsh\Desktop\new-study\infra-layout-recon`의 `scripts/recon/measure*.mjs`와 `src/app/dev/recon/`이다. 측정값은 세션 scratchpad의 `layout-recon/metrics*.json`에 있다. 그중 1단계와 관련된 것은 다음과 같다.

- **선택해도 관계가 약하게 보인다.**
  - 연결된 선의 굵기와 색이 그대로이고, 나머지만 22%로 흐려진다. 화면 픽셀 대비는 1.3~4:1에 그친다.
  - 영역 상자는 흐려지지 않는다.
- **함께 지나는 구간에 남은 문제 두 가지.** 조각은 지나는 선 묶음이 바뀌는 곳마다 끊긴다(`segments.ts`). 그래서 밝게 남는 공유 조각은 실제로 고른 선이 지나는 곳이다. 처음 측정에서 나온 "16곳"은 측정 기준이 잘못된 값이다. 실제로 남은 문제는 다음과 같다.
  - 갈림점 점(`edge-junction`)이 묶음 전체를 기준으로 밝게 남는다.
  - 종류가 섞인 조각은 가장 느린 종류 하나로 그려진다. 그래서 비동기 선을 골라도 요청선 모양으로 밝아진다.
- **연결 이름이 반복된다.** 고르면 연결 이름이 모두 켜져서 "HTTP 8080"이 십수 번 나온다.
- **평행선 간격이 좁다.** 서로 다른 선이 4~8px 간격으로 붙어 지나간다. 100노드 ALB는 연결이 25개이고, 쇼핑몰 샘플은 WAS 아래로 가로선 4줄이 지나간다.
- **영역 이름이 작다.** 기본 화면에서 7.9px까지 작아진다.
- **접힌 상자 이름이 잘린다.** 노드가 40개를 넘어 영역이 접히면 상자 이름이 "서…"처럼 잘린다.

## 목표

1. 노드나 영역, 연결을 고르면 이어진 선과 노드가 한눈에 도드라진다. 나머지는 확실히 뒤로 물러난다.
2. 함께 지나는 구간에서는 실제로 연결된 선이 지나는 부분만 밝아진다.
3. 고른 대상의 연결 이름이 같은 글자로 반복되지 않는다.
4. 서로 다른 선이 바짝 붙어 한 줄처럼 보이는 곳이 없어진다.
5. 영역 이름이 화면에서 늘 읽힌다. 접힌 상자 이름은 잘리지 않는다.
6. 측정값을 자동 테스트로 남겨서, 2~4단계에서 나빠지면 숫자로 알 수 있게 한다.

## 하지 않는 것 (2~4단계 몫)

- 외부 서비스 열의 배치와 줄기 다시 짜기(2단계). 외부 통로 간격(`CHANNEL_STEP`)은 목표 4 때문에 이번 단계에서 손댈 수 있다. 통로 구조 자체는 그대로 둔다.
- 배치 방향, 줄바꿈, 화면 비율, 포트 제약(3단계).
- 접기 방식과 확대 단계별 표시(4단계). 노드 40개를 넘으면 한꺼번에 접는 지금 규칙은 그대로다.

## 실패로 보는 것

- 강조 때문에 선 종류(요청·비동기·복제·관리) 구분이 사라진다.
- 고르지 않은 평소 화면이 지금보다 어지러워진다.
- 이미지로 내보낸 그림에 강조나 흐림이 남는다.
- 움직임 줄이기 설정을 켰는데 빛이나 전환이 움직인다.
- 노드 수가 많을 때 고르는 동작이 눈에 띄게 느려진다.

## 사용자가 정한 것

사용자는 브라우저 비교 화면을 보고 아래 안을 골랐다.

### 1. 강조 방식: "굵게 + 은은한 빛, 선 종류 색 유지"

**이어진 선**
- 2.5px로 굵고 밝게 그린다.
- 둘레에 옅은 빛을 준다. 비교 화면에서는 6px 폭에 흐림 2.4, 불투명도 0.35였다.
- 화살표도 함께 키운다. 비교 화면에서는 5→6.5였다.

**선 종류 구분**
- 요청·비동기·복제·관리 선의 모양(실선, 점선, 겹선)은 그대로 둔다.
- 종류별 색 계열도 유지한다.
- 비교 화면은 요청선만 있어서 밝은 청회색 `#B9C8DE`, 빛 `#AFC3E0`로 그렸다. 종류마다 어떤 밝은 색을 쓸지는 아래 「만드는 사람에게 맡기는 것」에 있다.

**나머지 대상**
- 이어지지 않은 선과 노드는 지금보다 훨씬 흐리게 한다. 비교 화면에서는 선 12%, 노드 18%였다.
- 이어진 노드가 하나도 들어 있지 않은 영역 상자도 흐린다. 비교 화면에서는 35%였다.
  - 상자 안에 이어진 노드가 있으면 바깥 영역까지 모두 밝게 둔다.
  - 고른 대상이 영역이면 그 영역도 밝게 둔다.

**고른 대상** 고른 노드의 금색 테두리는 지금처럼 둔다.

### 2. 함께 지나는 구간: "한 줄기로 묶기"

- 지금처럼 여러 선이 한 점에서 나와 줄기를 함께 타다 갈라지는 그림을 유지한다. ELK `mergeEdges`와 `segments.ts`의 공유 조각이 이를 그린다.
- 평소 모습은 바꾸지 않는다.
- 고를 때 그리는 방식은 사용자가 "고른 선을 위에 따로 겹쳐 그림"으로 정했다.
  - 공유 조각을 포함해 아래에 깔린 선은 모두 흐린 쪽에 둔다.
  - 이어진 선은 하나씩 처음부터 끝까지 자기 종류 모양(실선, 점선, 겹선)으로 그 위에 겹쳐 그린다.
  - 갈림점 점도 흐린다. 겹선 위에 있는 갈림점만 밝게 둘 수 있다.
  - 이미지로 내보낼 때는 겹선을 걷어 낸다.

### 3. 반복되는 연결 이름: "같은 이름은 한 번만, 개수와 함께"

- 고른 대상의 이어진 선 가운데 같은 이름이 여러 번 나오면, 갈라지기 전 줄기 위에 한 번만 쓴다. 예: `HTTP 8080 ×4`.
- 이름이 다른 연결은 각자 선 위에 그대로 둔다.
- 같은 이름의 선들이 줄기를 함께 타지 않고 각자 다른 길로 나갈 때(일부만 함께 탈 때 포함)는 사용자 선택을 따른다.
  - 고른 노드 바로 옆, 선들이 떠나는 쪽에 `HTTP 8080 ×N`을 한 번 쓴다.
  - 각 선 위에는 쓰지 않는다.
- 원칙: 고른 동안에는 같은 글자의 이름이 화면에 한 번만 나온다.

### 4. 평행선 간격

같은 줄기를 함께 쓰는 공유 구간이 아닌데 서로 다른 선이 나란히 지나가면, 그 사이를 16px 이상 벌린다.

적용 범위는 사용자가 정했다.
- **평소 화면에서는 0으로 만든다.** 평소 화면은 샘플, 노드 40개 이하 구성도, 40개를 넘어 접힌 기본 화면이다. 선이 노드에 붙는 끝 몇 px는 셈에서 뺀다.
- **큰 구성도를 모두 펼친 화면은 기준선만 지킨다.** 지금 값을 기록하고 나빠지지 않게만 한다. 0으로 만드는 일은 3단계(배치 모양)에서 한다.

### 5. 영역 이름 크기: "확대에 맞춰 보정"

- 멀리 볼수록 글자를 키워서 화면에서 늘 10px 이상이 되게 한다.
- 가까이 볼 때는 지금 크기(11px) 그대로다.
- 지금 `[data-zoom="far"]` 단계에서만 14px로 키우는 방식은 이 연속 보정으로 바꾼다.
- `--zoom` CSS 변수는 이미 있다(`Canvas.tsx` ZoomVar, `canvas.css`의 `--hit`).
- 상한은 사용자가 정했다.
  - 글자는 그 영역 상자 폭 안에서만 커진다.
  - 폭이 모자라면 말줄임(…)을 쓰고, 마우스를 올리면 전체 이름을 보여 준다.
  - 이름표가 영역 밖으로 넘치거나 노드를 덮지 않는다.
- 머리 칸 높이(캔버스 30px)도 상한이다(사용자 선택: "머리 칸 안까지만 키움"). 글자는 캔버스 약 19px까지만 커진다. 따라서 10px 보장은 배율 0.5 이상에서만이고, 그보다 멀리 보면 조금씩 작아진다. 아주 멀리 볼 때는 4단계(확대 단계별 표시)에서 다룬다.

### 6. 접힌 영역 상자: "상자 폭을 이름에 맞춤"

- 이름이 다 들어가도록 접힌 상자를 넓힌다.
- 최대 폭을 정해 두고, 그보다 길 때만 말줄임표를 쓴다. 이때 마우스를 올리면 전체 이름을 보여 준다.
- 폭은 기본 글자 크기(11px)를 기준으로 맞춘다. 멀리 볼 때 보정으로 커진 글자가 넘치면 5번의 말줄임 규칙을 따른다.

## 제약

- 색은 `src/styles/tokens.css` 토큰으로만 쓴다(`edges.css` 규칙). 새 강조색과 빛 색은 토큰으로 추가한다.
- 흰 바탕으로 내보내는 그림의 토큰 짝(`exportImage.ts`의 `LIGHT_TOKENS`)도 함께 둔다.
- 이미지 내보내기(`neutralizeClone`)는 늘 평상시 모습이어야 한다.
  - 새로 생기는 강조 클래스와 겹선은 걷어야 한다.
  - 빛 필터를 `<defs>`로 두면 복제본에서 id를 지우는 처리와 부딪치지 않게 한다.
  - 내보낸 그림은 지금처럼 연결 이름을 모두 넣는다. 이름 합치기는 고른 동안의 화면 표시에만 적용한다.
- `prefers-reduced-motion`에서는 전환을 끈다. 빛은 정지한 모양이라 그대로 둔다.
- 쌓는 순서는 `stacking.ts`를 따른다(영역 0~8, 선 9, 노드 10). 밝힌 선은 선 층 안에서 흐린 선보다 위에 그린다.
- 흐름 표시 움직임(`motion.ts`)은 지금처럼 동작해야 한다. 40개를 넘으면 고른 것과 닿은 묶음만 움직인다.
- 호버 강조도 같은 집합(`emphasis.ts`)을 쓴다. 호버를 어떻게 보일지는 아래 「내가 정한 것」을 따른다.
- 접근성은 그대로 유지한다.
  - 캔버스 Tab 한 번 + 화살표 이동.
  - 누르는 자리 24px.
  - 보조기기 이름(`ariaLabels.ts`).
  - 빛과 굵기는 시각 장식이고 의미는 기존 상태가 전한다.
- 기존 단위 테스트, 통합 테스트, E2E(`tests/e2e/phase3e.spec.ts`의 호버·선택 등)가 통과해야 한다. 기대값이 바뀌면 의도한 변경인지 확인하고 고친다.
- 문서 사이트 동기화 규칙을 따른다(메모리 `docs-site-sync`).

## 측정과 회귀 테스트

spike worktree에 있는 측정을 저장소 안의 자동 테스트로 옮긴다. 1단계에서 지킬 기준은 다음과 같다.

| 항목 | 기준 |
|---|---|
| 선택 시 밝힘 | 밝은 겹선은 이어진 선에만 있고, 겹선마다 그 선의 종류 모양을 쓴다. 밝은 갈림점은 겹선 위에만 있다 |
| 이름 반복 | 고른 동안 같은 글자의 연결 이름이 화면에 2번 이상 나오는 경우 0. 줄기가 없어도 같다 |
| 평행선 간격 | 공유 조각이 아닌 서로 다른 선이 16px 미만으로 나란히 지나는 길이 0. 평소 화면(샘플 5개, state-25, state-50·100의 접힌 기본 화면)에서 재고, 노드 끝 몇 px는 뺀다. 펼친 큰 화면은 기준선만 기록한다 |
| 영역 이름 | 배율 0.5 이상인 기본 화면과 '전체 보기'에서 화면 글자 10px 이상. 영역 폭이 모자라 말줄임된 이름은 예외로 따로 센다. 이름표가 영역 밖으로 넘치는 곳 0 |
| 접힌 상자 이름 | 최대 폭 안에 드는 이름은 잘리지 않음 |

나머지 측정값도 기준선으로 기록한다. 이 값들은 1단계에서 나빠지지만 않으면 된다.
- 교차 수
- 노드를 가로지르는 선 수(지금 0)
- 꺾임 수
- 가로:세로 비율

이 단계가 끝나면 같은 입력으로 전후를 비교해 보고한다.

## 내가 정한 것 (사용자 확인 필요)

- 호버는 선택보다 약하게 보인다. 이어진 선만 조금 굵게(1.8px 정도) 하고 빛은 없다. 나머지는 지금처럼 45%로 흐린다. 선택이 호버보다 앞서는 규칙도 지금 그대로다.
- 연결을 고르면 그 선과 두 끝 노드에 노드를 고를 때와 같은 강조를 준다.

## 만드는 사람에게 맡기는 것

- 선 종류별 밝은 색과 빛 색의 정확한 값. 어두운 바탕과 흰 바탕 내보내기에서 모두 종류 구분이 살아 있어야 한다.
- 흐림 정도의 최종값. 비교 화면 값에서 시작해 실제 화면에서 맞춘다.
- `×N` 이름을 줄기의 어느 지점에 놓을지. 갈라지기 전 공유 조각 위에 놓는다는 원칙만 지키면 된다. 줄기가 없으면 노드 옆, 선들이 떠나는 쪽에 놓는다.
- "노드 끝 몇 px"의 정확한 값.
- 16px 간격을 어떻게 확보할지. ELK `spacing.edgeEdge`, `CHANNEL_STEP`, 그 밖의 원인 가운데 무엇을 고칠지는 실측으로 정한다.
- 접힌 상자의 최대 폭 값.
- 회귀 테스트를 단위 테스트(배치 결과 계산)로 둘지 E2E(화면 측정)로 둘지.
