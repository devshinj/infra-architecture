# 요청 범위 넘침 점검

날짜: 2026-11-18. 브랜치 `feat/scope-eval`.

## 왜

Clef 의도 분류를 실제로 재 보니(새 유형 50문장) 분류는 병목이 아니었다. 판정 없음으로 떨어진 문장도 Qwen 이 맞게 처리했다. 의도와 결과가 어긋난 곳은 Qwen 이 요청하지 않은 것까지 바꾸는 쪽이다.

- "로드밸런서 … 웹 서버 앞에 추가해 줘" → 한 번은 명령 7개, 한 번은 28개(웹·WAS·DB 이중화, "경고를 해소할게요").
- "웹 서버 두 대에 WAS 세 대, DB 는 오라클" → 말하지 않은 DB 이중화, 지어낸 소프트웨어 이름(Tomcat 10 등).
- "메시지 큐 … WAS 뒤에 하나 넣어 줘" → 관계없는 결제 요청 연결을 지움.

지금 점검(`npm run eval:intent`)은 기대한 명령이 나왔는지를 주로 보고, 요청 밖을 건드렸는지는 몇 문장의 `forbid` 로만 본다. 프롬프트를 고치기 전에 넘치는 비율을 수치로 갖는다.

## 정한 것

### 넘침 (사용자)

한 실행에서 아래 중 하나라도 걸리면 넘침이다. 차례 시작 구성과 명령을 적용한 뒤 구성을 견주어 판정한다.

| 검사 | 넘침 |
|---|---|
| 기존 대상 | `touch` 에 없는 기존 노드·연결·영역이 바뀌거나 지워짐 |
| 새 노드 | 새 노드가 `newNodes`(기본 0)보다 많음 |
| 새 영역 | 새 영역이 `newGroups`(기본 0)보다 많음 |
| 새 연결 | 양 끝이 모두 기존 노드이고 둘 다 `touch` 에 없는 새 연결 |
| 속성값 | 새로 적힌 속성값이 `attrs` 에 없는 key 이고, 시작 구성의 어느 노드에도 같은 key·같은 값이 없음 |

- 속성값은 말하지 않은 값이면 모두 넘침이다(사용자). 기존 노드의 값을 새 노드에 복사한 것은 허용한다.
- 흐름 명령과 가정 명령은 세지 않는다.

### 만드는 법 (사용자)

- 기존 점검에 검사를 더한다. `cases.json` 문장의 `qwen.scope` 에 `{ touch, newNodes, newGroups, attrs }` 를 적는다.
- 새 문장에만 붙인다. 기존 42문장은 그대로라 기준 파일 비교가 유지된다.
- 넘친 실행은 그 문장의 Qwen 판정을 실패로 만든다. 표 아래에 범위를 잰 실행 중 넘친 수와 검사별 수를 낸다.
- 앱 코드는 바꾸지 않는다.

### 제 판단

- 판정 함수 `checkScope(scope, before, after)` 는 `scripts/eval-intent-lib.ts` 에 두고 단위 테스트를 붙인다.
- 기대(expect)가 틀린 실행도 범위는 따로 잰다(넘침 수가 기대 실패에 가려지지 않게).
- 기준 파일에는 문장별 넘친 실행 수(`scopeOver`)를 함께 남긴다. 비교 규칙은 바꾸지 않는다.

## 하지 않는 것

- 프롬프트 수정, Clef 로 그린 뒤 범위 검사하기. 이 수치를 본 다음에 정한다.
